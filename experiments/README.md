## 실행

**한 번에 전부 돌리기 (권장)**
```bash
pip install pyyaml
python experiments/run_all.py       # → experiments/RESULTS.txt
```

**[RESULTS.txt](RESULTS.txt)가 모든 수치의 단일 출처다.**
문서 여러 곳에 숫자를 옮겨 적으면 어긋난다 — 실제로 3곳이 어긋나 있었고, 이 파일을 만든 이유가 그것이다.
문서의 수치가 의심되면 여기와 대조한다.

**개별 실행**
```bash
pip install pyyaml
python experiments/gen_corpus.py       # 코퍼스 생성 (먼저 실행)
python experiments/cache_sim.py        # 실험 1: 캐시·배치
python experiments/retrieval_sim.py    # 실험 2: 검색·쓰기정책·현저성
python experiments/arms_sim.py         # 실험 3·4: arm 비교, 깊이별 교정

python experiments/vector_bench.py     # 실험 6: 브루트포스 벡터 검색 벤치
python experiments/param_sweep.py      # 실험 7: 파라미터 스윕 (τ, k, N)
python experiments/sensitivity.py      # 실험 8: 깊이 분포 민감도
python experiments/guard_sim.py        # 실험 9: 상태 가드 (정규식 vs 의미적 위반)
python experiments/mechanism_sim.py    # 실험 10: L9 부채·surfaced_count·커버리지

pip install sentence-transformers      # 실험 5만 추가 의존성 (~470MB 모델 다운로드)
python experiments/hybrid_sim.py       # 실험 5: BM25 vs Dense vs 하이브리드
```

전부 결정적(seed 고정)이라 몇 번을 돌려도 같은 숫자가 나온다.
`eval/corpus/`는 생성물이므로 지워도 된다 — `gen_corpus.py`가 다시 만든다.

## 왜 키 없이 가능한가

| 실험 | 재는 것 | LLM이 필요 없는 이유 |
|---|---|---|
| 1 캐시 | 접두사 안정성, 토큰 회계 | 캐시는 **접두사 일치 문제**다. 인과 마스크 때문에 토큰 회계만으로 결정된다 |
| 2 검색 | BM25 순위, 오주입 | BM25는 **어휘 통계**다. 로컬에서 완결된다 |
| 3·4 arm | evidence_recall, precision | **검색기가 못 찾은 걸 LLM이 답할 수는 없다.** 이건 품질의 **상한**이다 |

> **핵심: 품질의 상한은 LLM 없이 잴 수 있다.** 품질 자체는 못 잰다.

## 결과 요약

**실험 1 — 캐시·배치**
```
K1(기억이 앞)  캐시 24%  입력 $24.38/월
K3(빈도순)     캐시 49%  입력 $17.22
+ 청크 축출    캐시 79%  입력  $9.12      ← 슬라이딩 윈도우가 더 큰 레버
```
🆕 **최근 N턴을 1턴씩 미는 것은 append가 아니라 evict다.** 매 턴 접두사를 깨뜨린다.

**실험 2 — 검색**
```
한국어 토큰화   어절 40%  vs  문자 bigram 60%  (recall@5)
쓰기 정책      전부 색인 → top-5의 4~5개가 잡담 / 추출만 색인 → 0/5
importance     곱셈 ❌ 덧셈 ❌ 하드필터 ✅      ← ADR-005 수식 수정
```

**실험 3·4 — arm 비교 (참조 깊이 가중)**
```
A2 Window-only(15)   75%     ← 단순 baseline이 4분의 3을 커버
C2 추출단위 RAG        81%     ← 정교한 검색이 6%p만 더
G1 현행 재현(추정)      95%
F1 제안안             96%  (precision 38% vs G1 26%)
A1 Oracle           100%     ← 상한
```
🔴 **MemDelta 재현.** 그리고 **Window와 Retrieval은 보완재다** (75%/81% → 결합 95%).

**실험 5 — 하이브리드 검색 (내 주장이 반증됨)**
```
              BM25   Dense   Hybrid(RRF)
어휘형 평균순위   1.2    1.2    1.2      ← BM25가 고유명사에서 이기지 못함
의역형 평균순위   4.2    1.2    2.6      ← 하이브리드가 dense 단독보다 나쁨
```
🔴 [FP-4](../docs/03-architecture-modules.md)의 예측이 빗나갔다. **다만 검색 대상이 22개뿐이라 실패 조건 자체가 없었다** — 과신한 것도, 제대로 테스트 못 한 것도 둘 다 사실이다.

**실험 6 — 브루트포스 벡터 검색 (ADR-003 확인)**
```
256차원 int8   3,000개 → 0.13 ms / 0.73 MB
              100만개 → 18.6 ms / 244 MB
Qdrant 네트워크 왕복(문헌값)  1~5 ms
```
✅ 네트워크 왕복만으로도 브루트포스보다 10~40배 느리다. 그리고 **카디널리티 추정이 300배 틀려도 결론 불변.**

**실험 7 — 파라미터 스윕**
```
τ 하드 게이트   0.2~0.4 어디든 평평, 0.5부터 recall 붕괴   → 내 추정(0.2) 안전
N 윈도우        무릎 = 10턴 (5턴 81% → 10턴 96%)          → 내 추정(10~15) 맞음
k 주입 개수     ⚠️ 측정 불가 — 질문마다 정답이 1개라 k=1이 자동 최적
```
⚠️ k는 **평가 설계의 산물**이라 이 결과로 바꾸면 안 된다. 스윕이 항상 답을 주지는 않는다.

**실험 8 — 깊이 분포 민감도 (가장 하중이 큰 가정)**
```
얕은 참조 95%  →  검색 이득  4%p   ❌ 만들 이유 없음
얕은 참조 75%  →  검색 이득 21%p   ⚠️ 애매        ← 내 추정이 여기
얕은 참조 50%  →  검색 이득 44%p   ✅ 필수
```
**검색 이득이 14배 움직인다.** 손익분기는 얕은 참조 **약 85%**.
✅ 반면 **precision 우위(F1 38% vs G1 22%)는 모든 분포에서 recall이 동률**이라 분포와 무관하게 유지된다.

**실험 9 — 상태 가드 ("정규식이면 충분"은 과했다)**
```
순수 정규식        정밀도  50%  재현율 57%   ← 인용·회상에서 오탐
+ 억제 문맥 처리    정밀도 100%  재현율 57%   ← 0.7μs, 사실상 공짜
```
🔴 **의미적 위반(금지어 없는 상태 위반)은 원리적으로 못 잡는다.** 스키마 비교는 NLI를 대체하지 않고 **필요한 양을 줄인다.**
⭐ 그리고 의미적 위반은 **사후 검증보다 사전 주입(상태를 컨텍스트에 넣기)**이 낫다.

**실험 10 — 메커니즘 검증 (설계만 하고 안 돌려본 것들)**
```
L9 부채 트리거    🔴 백오프 없음 → 4세션 연속 발화 = 집착
                 🔴 시계 모호(wall vs session) → 트리거 미발화
L6 surfaced      페널티 무릎 = 0.1 (재주입 89% → 11%, relevance 손실 1%)
M  커버리지        5/5 정확 — 룰 판정이라 결정적
```
🔵 **모호한 발화("요즘 어때")엔 평균 relevance가 0.10.** 무엇을 꺼내든 우연이다 — 게이팅이 막아야 할 지점.
→ 스키마에 `last_attempted_at`·`attempt_count`·`trigger_clock` 3개 필드 추가.

## ⚠️ 한계 — 이 실험들이 말할 수 없는 것

**측정 불가 (API 키 필요)**
- 응답 품질, 페르소나 유지, 능동 소환, 서사 부채 이행
- **L3(활용) 실패** — 정답을 컨텍스트에 넣어줘도 모델이 안 쓰는 경우
- Interactions API의 실제 과금 토큰

**모델링의 한계**
- 실험 1은 **시뮬레이션이지 실측이 아니다.** Provider의 최소 토큰 임계·TTL·암묵적 캐싱 동작을 반영하지 않았다
- 실험 2에 **dense 검색이 없다.** 임베딩 모델을 안 붙여서 하이브리드 비교를 못 했다
- **형태소 분석기를 못 썼다.** 문자 bigram은 nori의 대리물이다

**데이터의 한계**
- 코퍼스가 **합성이고 산문 품질이 낮다.** 검색 실험 전용이며 응답 품질 평가에는 못 쓴다
- **LLM이 쓴 데이터로 LLM 시스템을 테스트하는 순환성**은 여기 없다(템플릿 생성이라). 대신 **어휘 다양성이 실제보다 훨씬 낮다**
- 추출 항목이 22개뿐이라 **top-5 순위의 통계적 변별력이 약하다**
- 깊이 가중치(75/20/5)는 **추정값**이다

> **결론의 유효 범위: 상대 순위와 방향성.** 절대 성능은 예측할 수 없다.

| arm | 정답 |
|---|---|
| **제안안** | **19/26 = 73%** |
| **현행 재현(G1)** | **17/26 = 65%** |
| Oracle *(정답 근거만)* | 17/26 = 65% |
| 최근 30턴 | 6/26 = 23% |

```
L3 활용 실패 35%  >  L2 검색 실패 8%
```
**메모리 구조를 완벽히 고쳐도 상한이 낮다** → 배치·프롬프트가 먼저.
다만 **메모리는 품질을 6배 올린다**(12% → 73%). 두 작업은 경쟁하지 않는다.

⚠️ 제안안 vs 현행은 **2문항 차 = 잡음 범위**다. 우열을 단정하지 말 것.

⚠️ **무료 티어 한도는 모델별이다.** `gemini-3.6-flash`는 **하루 20건**이라 104콜이 불가능했다.
`gemini-3.1-flash-lite`로 완주했다. 쿼터 소진 시 진행분을 잃지 않도록 **매 콜 체크포인트**를 둔다.

무료 키: <https://aistudio.google.com/apikey> · 총 **104콜**(26문항 × 4arm), 분당 10 기준 **~11분**.

**왜 무료 티어로 되는가.** [eval/README §7](../eval/README.md)의 Step 0(L3 활용 실패율)은
정답이 문자열이라 **LLM 심판이 필요 없다.** 규칙 채점으로 끝난다.

| arm | 무엇을 보나 |
|---|---|
| A0 기억없음 | 바닥 |
| **A1 Oracle** | **상한** — 근거를 확실히 줘도 못 쓰면 **L3 활용 실패** |
| A2 최근 30턴 | Window 단독 |
| C 제안안 | 프로토타입의 실제 읽기 경로 |

**A1과 C의 격차가 곧 구조 개선으로 얻을 수 있는 최대치다.**

⚠️ **행동 프로브 18개는 안 돌린다.** 심판이 필요한데 같은 벤더뿐이라
[자기선호 편향](../docs/05-cost-latency-reality.md)이 생긴다. **편향된 숫자를 내느니 없는 게 낫다.**
PPR·페르소나 유지는 여전히 미측정으로 남는다.

⚠️ 무료 티어는 입력이 **구글 제품 개선에 사용된다.** 이 코퍼스는 전부 합성이라 무방하지만
**실유저 대화로는 절대 돌리면 안 된다.**

> 🔴 **채점기를 만들다 제 검색기와 똑같은 함정에 빠졌다.**
> 부분문자열로 채점하니 `민감하다` ≠ `민감하잖아`라 **정답이 오답 처리**됐다 —
> [FP-4](../docs/03-architecture-modules.md)의 교착어 문제가 이번엔 **채점기에서** 재현됐다.
> 어미 정규화를 넣고, **부분 일치는 자동 오답이 아니라 '확인필요'로 뺀다.**
> 약어·의역은 어휘 채점으로 원리적으로 못 가른다. 조용히 깎아내리느니 사람이 본다.

### 🔧 `consistency_audit.py`는 실험이 아니라 **도구**다

문서가 44편이고 실험을 18개 돌리며 계속 고쳤다. **같은 숫자가 여러 문서에 인용**되는데,
한 곳만 고치면 문서가 서로 다른 말을 한다. 링크 검사는 하고 있었지만 **숫자 검사는 없었다.**

실제로 돌려보니 **실험 개수와 ADR 편수가 문서마다 달랐다**(18/17/15/10, 13/10/6).

⚠️ `PROGRESS.md`와 초기 계획서는 **시간순 기록물이라 옛 값이 남아 있는 게 정상**이다.
안 빼면 감사가 정상인 것을 계속 빨갛게 만들고, **그러면 아무도 안 본다.** 그래서 제외한다.

| # | 결과 |
|---|---|
| **14** | 🔴 *"제안안 73% vs G1 65%"*의 **2문항 차는 잡음**이었다. arm 내 흔들림과 같다 |
| **15** | 🔴 요약 *"전체 재작성"*의 입력을 안 정했다 — 400세션에서 **760배** 차 |
| **16** | 🟡 기억 주입 **0/45.** 내 위험 평가가 과장이었다 |
| **17** | 🔴 **첫 세션 환각 83%** → 프롬프트 3줄로 **17%** |
| **18** | 🔴 **stale fact 색인 누수**(23턴→0). 갱신이 파생물에 전파 안 됐다 |

⚠️ **16·17은 자동 판정이 크게 틀렸다.** 17은 정규식이 8%로 봤는데 실제는 83%다.
*"모른다고 했나 vs 지어냈나"*는 어휘로 안 갈린다 — 수기 판정을
[COLDSTART_ADJUDICATION.yaml](COLDSTART_ADJUDICATION.yaml)에 근거와 함께 남겼다.
