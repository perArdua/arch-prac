# 프로토타입 — 구현하니 드러난 것들

> 코드: [prototype/memory.py](../prototype/memory.py) · [prototype/demos/demo.py](../prototype/demos/demo.py) · [prototype/soak.py](../prototype/soak.py)
> 실행: `python prototype/demos/demo.py` — **표준 라이브러리만** (sqlite3, re, json)
> 목적은 성능이 아니라 **설계가 놓친 것을 드러내는 것**이다.

수기 세션을 쓰다가 [U10](02-problem-definition.md)과 [해석 형성 정책](06-data-model.md)이 나왔던 것처럼,
구현하니 또 나왔다. **패턴이 반복된다 — 만들어보면 설계할 때 안 보이던 게 보인다.**

## 구현 범위

[06 데이터 모델](06-data-model.md)의 부분집합을 SQLite로. L0 원본 / L1 캐릭터(버전 고정) / L2 관계 / L3 씬 / L4 요약 2층 / L5 사실 / L6 사건 / L9 부채 / M 커버리지 / provenance.

읽기 경로는 [ADR-005 수정판](adr/ADR-005-forgetting-salience.md)의 4단계를 그대로 — 색인 선별 → **하드 게이트** → 가중 정렬 → 임계 컷.
파라미터는 [실험 7 스윕](11-experiment-results.md) 결과(τ=0.2, N=10, 페널티 0.1, 청크 10).

## 🔴 발견 1 — 어미 정규화 없이는 정답이 탈락한다

첫 실행에서 이렇게 나왔다.

```
턴 703  "나비 아팠던 거 기억나?"
  🚫 rejected  나비가 갑자기 아파서 응급실에 감    relevance 0.11 < θ
```

**정답이 임계에 걸려 탈락했다.** 이유는 `아팠던` ≠ `아파서` — bigram이 안 맞는다.

> **[FP-4](03-architecture-modules.md)의 교착어 문제가 구현에서 그대로 재현됐다.**
> 문서에서는 *"형태소 분석이 필수"*라고 썼는데, **구현할 때는 bigram으로 대충 넘어갔다.**
> 문서에 쓴 것과 코드에 넣는 것은 다른 일이다.

어미를 벗기는 최소 정규화(`_stem`)를 넣자 **score 0.48로 1위 검색**됐다.

```python
_ENDINGS = re.compile(r"(었|았|였|겠|시|으)?(다|는|은|을|던|서|고|…)$")
```

⚠️ 이건 nori의 대용품이지 대체재가 아니다. 실서비스에서는 형태소 분석기를 써야 한다.
**다만 "없으면 좋은 것"이 아니라 "없으면 정답이 탈락하는 것"임이 확인됐다.**

## 🔴 발견 2 — 조건부 존재 블록이 접두사를 깨뜨린다

부채(L9)는 **결정적 주입** 대상이라 앞쪽(변동성 6)에 뒀다. 그런데:

```
턴 701 [세션 시작]  … relationship, digest, debt, scene, recent …   ← 부채 있음
턴 702              … relationship, digest, scene, recent …         ← 부채 없음(백오프)
→ 공통 접두사 57%
```

**부채가 나타났다 사라질 때마다 그 뒤 전부가 무효화된다.**

> **여기서 개념 하나를 잘못 쓰고 있었다.**
> ```
> 결정적 주입 = "조건이 맞으면 반드시 들어간다"
> ≠ "앞쪽에 놓는다"
> ```
> [02 P4](02-problem-definition.md)에서 *"상태는 결정적으로 주입한다"*고 하면서 **암묵적으로 "앞쪽"을 함의**했다.
> 그런데 **존재 자체가 조건부인 블록은 뒤쪽이 맞다** — 나타났다 사라져도 깨뜨릴 게 적다.
> 그리고 lost-in-the-middle상 **끝도 고주목 위치**라 손해가 아니다.

부채를 뒤로(변동성 8.5, `recent` 다음) 옮기자 **접두사 57% → 100%.**

**일반화:** 블록을 정렬할 때 기준이 세 개다.
```
① 공유 범위 (전 유저 > 캐릭터 > 방)
② 내용 변경 빈도
③ 존재 변경 빈도   ← 새로 발견. 있다가 없어지는 것도 캐시를 깬다
```
[ADR-007](adr/ADR-007-context-packing-cache.md)에는 ①②만 있었다.

## 🔴 발견 3 — 두 방어선의 공을 구별해야 한다

*"마지막이라 아쉽다"* 턴에서 **크로와상이 안 나왔다.** 처음엔 *"하드 게이트가 막았다"*고 데모에 썼다.

**틀렸다.** provenance를 보니:
```
🚪 gate  차단  과거 참조 신호 없음
```
**게이트가 검색 자체를 막았다.** 하드 게이트는 돌지도 않았다.

> 두 방어선이 **직렬로** 있으면 앞의 것이 막을 때 뒤의 것은 검증되지 않는다.
> 그런데 리포트에는 *"하드 게이트가 빵 유언을 막는다"*고 쓰기 쉽다.
> **어느 층이 실제로 일했는지는 provenance 없이는 구별 불가능하다.**
>
> → [05 §5](05-cost-latency-reality.md)에서 *"provenance를 1급 요구사항으로"*라고 한 것의
> **첫 번째 실제 효용이 "내 주장의 오류를 잡은 것"**이었다.

과거 참조 표현이 있는 턴(*"나비 아팠던 거 기억나?"*)에서는 게이트가 통과하고, **거기서 하드 게이트가 실제로 일한다:**
```
✅ retrieved  나비가 갑자기 아파서 응급실에 감      score 0.48
🚫 rejected   지우가 점심에 크로와상 먹고 아쉽다고 함  importance 0.05 < τ
🚫 rejected   봄나들이에서 나비(곤충)를 봄           importance 0.10 < τ
```
**어휘 방해물(나비=곤충)까지 importance로 걸러진다.** [실험 5](11-experiment-results.md)에서 심은 X001이 여기서 작동한다.

## 🔴 발견 4 — `superseded_by`를 넣어놓고 로직은 없었다

`prototype/demos/fact_demo.py` — bi-temporal 무효화를 구현하려니 **문서에 없는 결정 네 개**가 필요했다.
그리고 **규칙을 세 번 고쳤다.** 매번 실행이 틀렸다고 알려줬다.

| 입력 | 1차 규칙 | 2차 | **최종** |
|---|---|---|---|
| 이직 (직업, 정당한 갱신) | 🛑 보류 ❌ | 🛑 보류 ❌ | **🔄 무효화** ✅ |
| "우리 오빠" (U10, 거짓) | ➕ 병존 ❌ | 🛑 보류 ✅ | **🛑 보류** ✅ |
| 코코 (반려동물 혼동, 거짓) | 🔄 무효화 ❌ | 🛑 보류 ✅ | **🛑 보류** ✅ |

**① 술어 카디널리티가 없었다.** `직업`은 하나, `가족`은 여럿. 이게 없으면 무효화할지 병존할지 못 정한다.

**② 다중값 술어에도 confidence floor가 필요하다.** 첫 구현은 `many`면 무조건 병존시켰다 → **없는 "오빠"가 그냥 들어갔다.** 카디널리티 방어는 단일값만 지킨다.

**③ 첫 규칙이 실행하자마자 깨졌다.** *"기존보다 margin(0.15)만큼 더 확신해야 덮는다"* — 기존이 0.9면 **1.05를 요구하는데 최대가 1.0**이다. **정당한 갱신도 영원히 보류된다.**

### ④ ⭐ 가장 깊은 것 — "갱신"과 "모순"을 구별할 축이 없었다

②③을 고치고 나니 이번엔 **재확인이 사실을 화석화**시켰다. `mention_count`가 오를 때마다 `confidence`가 올라 갱신이 점점 어려워지고, 결국 아무것도 못 바꾼다.

근본 원인은 이것이다.
```
"이직했어"      기존과 다른 값 → 세상이 변한 것.    허용해야 한다
"우리 오빠가…"  기존과 다른 값 → 유저가 잘못 안 것.  막아야 한다
```
**둘 다 "기존과 다른 값"이다.** confidence로는 구별할 수 없다 — 유저가 자기 오빠를 확신해서 말할 수도 있다.

> **→ 술어에 `mutability`가 필요하다.** 직업·거주지는 자주 변하고(high), 가족·반려동물 이름은 거의 안 변한다(low).
> 가변성이 높으면 갱신을 쉽게 허용하고, 낮으면 높은 확신을 요구한다.
>
> **이건 스키마를 그릴 때 전혀 안 보였다.** `superseded_by` 컬럼 하나로 다 되는 줄 알았다.

**최종 규칙**
```
같은 값        → mention_count++ (강화)
many + 저확신  → 보류 (confidence < 0.6)
one  + 충돌    → confidence < 기존 − 허용치(high 0.25 / mid 0.10 / low −0.05)
                 이면 보류 + 유저 확인 요청, 아니면 무효화
```

**`held`(보류)가 [U10](02-problem-definition.md)에 대한 데이터 계층 방어선이다.** 프롬프트로 *"유저가 틀리면 정정해"*라고 쓰는 것만으로는 부족하고, **애초에 거짓이 사실 테이블에 안 들어가야** 한다.

## 🔴 발견 5 — "3회 이상이면 해석 생성"인데 **무엇을 3회 셀지**를 안 정했다

`prototype/demos/interpret_demo.py` — 수기 세션에서 도출한 최소 근거 수 정책을 구현하려니 바로 막혔다.

**3회를 세려면 ① 개별 관찰이 저장돼 있어야 하고 ② 두 관찰이 "같은 패턴"인지 판정할 수 있어야 한다.**
[06 L8](06-data-model.md)에는 `interpretation` 테이블만 있고 **관찰을 담을 곳이 없었다.**

### 자유 서술 + 어휘 유사도 → 어떤 임계값도 작동하지 않는다

| 임계 | 결과 |
|---|---|
| **0.20** | 회피 3건 + 칭찬거부 2건이 **한 덩어리** → 잘못된 해석 생성 ❌ |
| **0.30** | 회피 3건이 **각각 흩어짐** → 해석이 아예 안 생김 ❌ |
| 0.45 | 동일 ❌ |

원인은 단순하다.
```
"힘든 얘기 하다가 젤리 얘기로 화제를 돌렸다"   ← 회피
"칭찬을 받자 화제를 돌렸다"                  ← 칭찬거부
```
**둘 다 "화제를 돌렸다"로 끝난다.** 표면이 같고 계기가 다르다.

> ⚠️ **그리고 더 나쁜 비대칭이 있다.** 칭찬거부는 문장이 거의 같아서 잘 묶이는데 **회피는 상황마다 달라서 안 묶인다.**
> **표면 다양성이 높은 패턴일수록 어휘 클러스터링이 실패하는데, 중요한 패턴일수록 다양하게 나타난다.**

### 구조화하면 결정적으로 된다

관찰을 **(계기, 반응, 극성)** 삼중항으로 저장하면:

| (계기, 반응) | 횟수 | 판정 |
|---|---|---|
| (힘든_얘기, 화제전환) | **3** | → 해석 생성, confidence 0.35 *(반증 1건 반영)* |
| (칭찬, 화제전환) | 2 | → 보류 |
| (힘든_얘기, **직면**) | 1 | → **같은 계기, 다른 반응 = 반증** |

- **계기가 다르면 반응이 같아도 안 뭉친다** — 회피와 칭찬거부가 갈린다
- **반증 처리가 여기서 처음 가능해진다** — 자유 서술로는 반례인지 사례인지 **구별 자체가 안 됐다**

> **→ [L8](06-data-model.md)에 `observation` 층을 추가한다.** `interpretation`은 직접 쓰는 게 아니라 관찰 집계에서 파생된다.
> 그리고 **관찰 추출은 LLM이 하되 자유 서술이 아니라 이 삼중항으로 뽑게** 해야 한다.
>
> **이게 이 실험의 진짜 산출물이다.** *"해석 누적은 LLM이 필요하다"*는 이미 알던 것이고,
> **"LLM에게 무엇을 시켜야 하는가"**가 새로 나왔다. 자유 서술을 시키면 나중에 아무것도 못 한다.

## 🔴 발견 6 — 설계 문서에 있는 블록을 구현이 빼먹었다

[15 §2](15-read-path-prompt.md)에서 컨텍스트를 `[알고 있는 것]`(항상 주입)과 `[꺼낼 만한 것]`(이번 턴 검색)으로 나눠 설계했다. **`build_context`는 후자만 구현했다.**

`facts_at()`은 존재하는데 `fact_demo.py`에서만 불렸고 **읽기 경로에 연결된 적이 없다.** 데모가 사실을 별도 스크립트로 확인한 탓에 **읽기 경로에 구멍이 있다는 걸 아무도 못 봤다.**

720턴 코퍼스 + QA 문항으로 재니 이렇게 나온다.

| 설정 | 근거 도달 | 검색 기여 | 트랩 | p50 토큰 |
|---|---|---|---|---|
| **A.** 검색만 (원래 구현) | 4/18 = 22% | 4 | 없음 | 490 |
| **B.** + `[알고 있는 것]` 전량 | 10/18 = **56%** | 0 | **주입됨** 🔴 | 799 |
| **C.** + 상시성 필터 | 9/18 = 50% | 0 | 없음 | 689 |
| **D.** + [실험 12](11-experiment-results.md) (θ·게이트) | 11/18 = **61%** | **1** | 없음 | 711 |

> A~C는 **발견 당시 파라미터로 고정**해서 잰다. 이후 실험 12가 θ와 게이트를 바꿔 기본값이 달라졌는데,
> 새 기본값으로 A~C를 돌리면 **발견 자체가 재현되지 않는다.** D가 현재 상태다.

> **10줄로 회상이 22% → 56%가 됐다.** 검색기 개선이 아니라 **설계 문서에 이미 있던 것을 구현하는 것**이 가장 큰 이득이었다.

**그리고 이게 시뮬레이션이 왜 안 보였는지를 설명한다.**
[실험 1](11-experiment-results.md)은 BM25 문자 bigram으로 `recall@5 = 70%`를 냈다. 같은 데이터인데 실제 구현은 22%였다. **시뮬레이션은 검색기를 격리해서 쟀고, 실제로는 게이트·임계·주입을 전부 통과해야 한다.** 파이프라인 전체는 부품보다 훨씬 나쁘다. 🔄 *«같은 데이터»는 같은 코퍼스라는 뜻까지만 참이다 — 문항(10 vs 18)·색인 단위(원본 턴 720 vs 사건 요약)·채점기(BM25 vs `coverage`)·지표(recall@5 vs 근거 도달)가 넷 다 다르고, 격차 중 채점기 몫은 잰 적이 없다([처분표 ⛔13](17-gap-disposition.md) · [ADR-015](adr/ADR-015-retrieval-modes.md) «미해결»).*

---

## 🔴 발견 7 — 그 수정이 게이트를 우회하는 길을 뚫었다

B 행의 트랩 열을 보라. `F007_TRAP`(크로와상, importance **0.05**)이 *"오늘 좀 피곤하네"* 같은 평범한 턴에도 들어간다. **유사 서비스 A의 «빵 유언»을 그대로 재현한 것이다.**

```
검색 경로     색인 → 하드 게이트 τ → 가중 정렬 → 임계 컷 θ     ← 4단 방어
결정적 주입   (없음)                                          ← 무방비
```

[ADR-005](adr/ADR-005-forgetting-salience.md)에서 하드 게이트를 세우면서 **검색 경로만 생각했다.** 결정적 주입은 "확실한 것만 넣으니 안전하다"고 암묵적으로 가정했는데, **틀렸다.** 확실한 것과 넣을 만한 것은 다르다.

> **일반화:** 방어선은 경로마다 필요하다. 한 경로에 세운 방어를 다른 경로가 우회하면 방어가 없는 것과 같다. **"어느 경로로 컨텍스트에 들어올 수 있는가"를 전수 열거**하지 않으면 반복된다.

## 🔴 발견 8 — importance로는 못 거른다. 다섯 번째 술어 속성이 필요했다

트랩의 importance는 0.05다. 그러니 importance로 거르면 될 것 같다. **틀렸다.**

```
"지우가 어제 발목을 삐었다"     importance 높음 · 그런데 상시 아님 (곧 낫는다)
"지우는 카페인에 민감하다"      importance 중간 · 상시           (체질이다)
```

importance는 *"이 기억이 중요한가"*를 재는데, 여기서 필요한 건 *"이게 캐릭터가 **항상** 알고 있어야 하는 종류인가"*다. **두 축은 직교한다.**

[발견 4](#-발견-4--superseded_by를-넣어놓고-로직은-없었다)에서 *"갱신과 모순을 구별할 축이 없었다"*며 **가변성(mutability)**을 추가했다. 같은 일이 또 일어났다.

| 속성 | 무엇을 가르나 | 언제 생겼나 |
|---|---|---|
| 카디널리티 | 하나인가 여럿인가 | 발견 4 |
| 가변성 | 이직인가 오인인가 | 발견 4 |
| **상시성(standing)** | **속성인가 사건인가** | **발견 8** |

`일상_사소` 술어는 상시가 아니다 → 결정적 주입에서 빠지고 **검색 경로로만 도달**한다. 트랩이 사라지고 토큰도 799 → 689로 줄었다. 회상 1건 손실은 `일상_사소` 문항이고, **그건 원래 검색이 맡아야 할 몫이다.**

> **패턴:** 술어에 필요한 속성이 세 번 다 **구현하다가** 나왔다. 스키마를 종이 위에서 완성할 수 없다는 증거다.

## ⚠️ 그리고 남은 불편한 숫자 — 검색의 순증 기여가 0이다

C 설정에서 `[알고 있는 것]`이 9건을 넣고 **검색이 추가로 넣은 건 0건**이다.

아키텍처 복잡도의 대부분(BM25/dense/hybrid, importance 가중, θ, top-k, 게이팅)이 검색 경로에 있는데, **이 평가에서 그 경로의 순증 기여는 0이다.**

**이걸 "검색은 필요 없다"로 읽으면 안 된다.** 세 가지가 걸린다.

1. **게이트가 병목이다.** QA 26문항 중 16개가 게이트에 막혔다. *"나 이직 준비하고 면접 몇 번 봤더라"*에는 `기억/그때/저번` 같은 과거 참조 표현이 없다. 룰 기반 게이트가 자연스러운 질문을 못 알아본다 → [실험 τ·θ 스윕](11-experiment-results.md)과 함께 봐야 한다
2. **사건은 사실이 아니다.** 남은 실패는 `multi_session`·`temporal`이고, 이건 결정적 주입으로 못 푼다. 사건을 전부 항상 넣으면 그게 full-context다
3. **문항 18개는 작다.** 순위는 읽되 백분율을 신뢰하면 안 된다

> ### 🔄 정정 — 순증 0은 검색기 탓이 아니었다 ([실험 12](11-experiment-results.md))
>
> 위 1번의 *"게이트가 병목"*이라는 제 추측을 실제로 재봤더니 **틀렸다.**
> 게이트를 완전히 열어도 회상이 1건도 안 올랐다.
>
> 진짜 범인은 **임계 θ**였다. 정답 근거의 질문↔요약 bigram 중첩이 대부분 **0.00~0.11**인데 **θ = 0.15**다.
> **정답이 임계 아래에 깔려 있었다.** θ를 0.05로 내리자 검색 순증이 0 → 1, 회상 9 → 11이 됐다.
>
> ```
> "검색 순증 0"  =  검색기의 무능  (X)
>                =  파라미터의 결과  (O)
> ```
> 그리고 그 θ=0.15는 [실험 7](11-experiment-results.md)에서 **검색기만 격리해 최적화한 값**이다.
> **부품에 최적인 값이 시스템에서는 최악에 가까웠다.**

> **그럼에도 방향은 유지된다.** *"검색을 잘하자"*보다 **"결정적으로 넣을 수 있는 것을 먼저 최대화하고, 남는 것만 검색에 맡긴다"*가 맞다.
> 다만 이유가 달라졌다 — 검색이 무력해서가 아니라, **결정적 주입이 더 싸고 더 확실하기 때문**이다.
> 검색은 사건·시간추론이라는 **자기 몫**이 있고, θ를 고치면 그 몫을 실제로 해낸다.

## 부수적으로 확인된 것 — 쓰기 지연은 전부 fsync다

`add_turn` p50 **5.19ms**, `build_context` p50 **0.81ms**. INSERT 한 줄이 SELECT 여러 번보다 느릴 리 없다. 커밋을 분리해 재보면:

```
턴마다 commit   p50 5.192ms
묶어서 commit   p50 0.001ms      ← 3,994배
```

**일의 비용이 아니라 내구성 보장의 비용이다.** 그래서 질문이 바뀐다 — *"쓰기를 어떻게 빠르게 하나"*가 아니라 **"무엇이 내구성을 필요로 하나."**

```
L0 원본 턴        유실되면 유저 발화가 사라진다        → 즉시 커밋
L5·L6·L4 파생물   L0에서 재생성 가능 (06 FP-7)        → 묶어서 커밋
```

[06 FP-7](06-data-model.md)에서 *"원본은 지우지 않는다"*를 논증했는데, **그 원칙이 성능 결정까지 결정한다는 걸 여기서 알았다.** 재생성 가능성은 저장 정책이자 내구성 정책이다.

## ⚠️ 이 프로토타입이 아닌 것

- **LLM이 없다.** 응답 생성·추출·요약이 전부 시드 데이터다. 컨텍스트 **조립**만 검증한다 🔄 *요약(P4)은 이제 로컬 `qwen3:8b`로 만든다(`summarize.py` · [ADR-016](adr/ADR-016-summary-layer.md)). 응답 생성·추출은 여전히 없다.*
- **룰 기반 게이트**다. 실제로는 경량 분류기가 나을 수 있다
- **`_stem`은 장난감**이다. nori 대용품이지 대체재가 아니다
- 사실(L5) 갱신·무효화, L8 해석 생성, Reflection은 **미구현**이다 🔄 *사실 갱신·무효화는 있다 — 카디널리티·가변성·상시성으로 갱신과 모순을 가르는 사실 upsert 경로와, 파생물까지 따라가는 무효화 전파(실험 18). 미구현으로 남는 것은 L8 해석 생성과 Reflection이다.*
- 동시성·트랜잭션 경계·마이그레이션 없음 🔄 *마이그레이션은 있다 — `_migrate`(스키마 v5 · `prototype/tests/test_migrate.py`).*

**그럼에도** 이 400줄이 설계 결함 **여덟 개**를 잡았다. 그게 프로토타입의 값이다.

그리고 발견 6~8은 **같은 코드를 실제 데이터에 통과시켰을 때만** 나왔다.
장난감 시드로는 5개까지가 한계였다. **규모가 결함을 드러낸다.**
