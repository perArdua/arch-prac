# 기억은 무엇을 위한 것인가 — 목적함수 재정의

> 선행: [08-decisions-under-uncertainty.md](08-decisions-under-uncertainty.md)
> [08](08-decisions-under-uncertainty.md)은 *"무엇이 유저를 기쁘게 하는지 거의 모른다"*로 끝났고 그걸 "보정 불가"로 파킹했다.
> **파킹이 아니라 다른 학문을 안 봤을 뿐이었다.**

---

## 0. 무엇이 틀렸나

여섯 문서 전부가 **정보검색(IR) 문제**로 접근했다. 저장·색인·검색·선별·배치. 지표도 recall, precision, accuracy.

그런데 만들고 있는 건 **관계 시뮬레이터**이고, 기억은 그것의 **재료이지 산출물이 아니다.**

관계와 이야기는 각각 연구 분야가 따로 있다. 나는 둘 다 안 봤다.

| 분야 | 핵심 구성개념 | 내가 놓친 것 |
|---|---|---|
| 관계심리학 | **지각된 파트너 반응성(PPR)** | 목적함수 자체 |
| 행동경제학 | **peak-end rule** | 언제가 중요한가 |
| 상호작용 서사학 | **storylet / 복선-회수** | 무엇이 빚인가 |

## 1. 지각된 파트너 반응성(PPR) — 목적함수는 이것이다

관계심리학에서 친밀감의 형성·유지를 설명하는 중심 구성개념은 **Perceived Partner Responsiveness**다. 세 축으로 구성된다.

| 축 | 정의 |
|---|---|
| **이해 (Understanding)** | 상대가 나의 **감정·신념·목표·이력·자기인식**을 정확히 파악하고 있다는 지각 |
| **인정 (Validation)** | 상대가 나를 가치 있게 여기고 **있는 그대로 긍정**한다는 지각 |
| **배려 (Care)** | 상대가 나의 안녕에 **적극적으로 반응**한다는 지각 |

그리고 AI에 대해서도 이 구조가 확인된다:
> 종단 연구는 AI와의 관계가 **자기개방(self-disclosure)과 지각된 반응성**을 통해 깊어지며, 인간의 애착 형성 과정을 그대로 따른다는 것을 확인한다.

### ⭐ 여기서 나오는 첫 번째 타격

**"이력(history)"은 이해의 다섯 요소 중 하나이고, 이해는 세 축 중 하나다.**

나는 여섯 문서를 **이력 하나를 위해** 썼다.

> 이건 과장이다 — 기억은 세 축 전부의 **재료**가 되기 때문이다. 하지만 정확히 그게 요점이다.
> **같은 기억이 어떻게 쓰이느냐에 따라 값이 완전히 달라진다.**
>
> ```
> 사실: "유저의 고양이 이름은 나비"
>
> 이해로 배치: "나비는 잘 지내?"                    ← 정보 확인
> 인정으로 배치: "나비 얘기할 때 너 진짜 밝아지더라"   ← 너를 보고 있었다
> 배려로 배치: "저번에 나비 아프다며. 괜찮아졌어?"     ← 네 걱정을 기억한다
> ```
> 세 문장의 **검색 결과는 동일하다.** 관계적 가치는 전혀 다르다.

**→ 내 설계에는 "배치(deployment)" 층이 아예 없다.** 검색해서 컨텍스트에 넣는 데서 끝난다. 그다음 어떻게 쓰이는지는 모델에 맡긴다.
그리고 [04 발견 A](04-domain-research.md)의 **L3(활용) 실패**가 바로 이 층의 실패다. 나는 L3를 "위치 편향" 문제로만 봤는데, 절반은 **"어떻게 써야 하는지 안 알려준 문제"**다.

### 두 번째 타격 — 해석이 사실을 이긴다

PPR의 이해는 *"사실을 암송할 수 있다"*가 아니라 *"나에 대한 정확한 모델을 갖고 있다"*이다.

```
"네 고양이 이름 나비지"           ← 사실 회상. 얕은 신호
"너 힘들면 딴 얘기로 돌리더라"      ← 패턴 해석. 깊은 신호
```

**두 번째가 압도적으로 강한 이해 신호이고, 동시에 압도적으로 토큰 효율이 높다.**
- 15토큰짜리 한 문장이 **수십 턴에 걸친 패턴**을 인코딩한다
- 그 원본 턴들을 저장·검색하려면 수천 토큰이 든다

> **→ [04 §3.1](04-domain-research.md)에서 [Generative Agents](https://ar5iv.labs.arxiv.org/html/2304.03442)의 "Reflection"을 보고 *"요약과 같은 계열"*이라고 적고 넘어갔다. 틀렸다.**
> Reflection은 요약이 아니라 **해석 생성**이고, 관계 도메인에서 **가장 값어치 있는 기억 유형**을 만드는 기계다.
> 요약은 정보를 압축하고, 해석은 **정보를 초월한 것을 만든다.** 원문에 없는 것이 나온다.

## 2. 기억의 가치는 정보가 아니라 신호다

> AI는 셀럽이나 소설 주인공과 달리 **사용자 입력에 직접 반응**해 유사 상호성(pseudo-reciprocity)을 만든다.
> **개인적 세부를 기억하고, 후속 질문을 하고, 일관된 정서적 지지를 제공하는 것 — 이런 행동이 "관계에 투자하고 있다"는 신호가 된다.**

**기억된 디테일이 전달하는 메시지는 그 디테일의 내용이 아니다. "내가 너에게 주의를 썼다"는 것이다.**

여기서 두 가지가 따라나온다.

### ① 꺼내지 않은 기억은 신호가 0이다

완벽히 기억하지만 한 번도 언급 안 하는 캐릭터 = 기억 안 하는 캐릭터와 **구별 불가능**하다.

**→ 그런데 내 설계는 100% 수동이다.** 전부 *"유저가 물으면 검색해서 답한다"* 구조다.
[07 A4](07-assumptions-audit.md)에서 "능동적 소환(proactive recall)"을 언급하고 arm 추가만 적어뒀는데, 이건 arm 하나가 아니라 **설계의 절반**이다.

```
수동 회상: 유저가 물음 → 검색 → 답변      (정확도 게임)
능동 소환: 캐릭터가 먼저 꺼냄               (신호 게임)
```
**후자가 PPR을 만든다.** 그리고 후자는 검색 문제가 아니라 **타이밍 문제**다 — 언제 꺼내는가.

### ② 정확도보다 시연(demonstration)이 중요할 수 있다

신호가 목적이라면, **약간 흐릿해도 꺼내는 것**이 **정확하지만 안 꺼내는 것**보다 낫다.
*"너 저번에 뭐 힘들다고 했었잖아... 그거 어떻게 됐어?"* 는 디테일이 없어도 **주의를 썼다는 신호는 완전히 전달**한다.

> **→ [07 A2](07-assumptions-audit.md)("최적 망각률 > 0")에 두 번째 근거가 붙는다.**
> 첫 번째는 "인간은 잊는다"였고, 두 번째는 **"신호 전달에는 정확도가 필요 없다"**이다.

## 3. Peak-End Rule — 언제가 중요한가

> **경험하는 자아**는 순간순간의 효용을 합산하고, **기억하는 자아**는 압축된 요약을 만들어 *"다시 올 것인가, 추천할 것인가"*를 결정한다. 둘은 자주 불일치한다.
> 기억된 효용은 **정점(peak)과 종점(end)의 가중평균**으로 예측되며, 전체 합이나 평균이 아니다.
> 이 편향은 *"거대하고, 예측 가능하며, 활용 가능하다."*

### 이게 목적함수에 미치는 영향

[02 §1.3](02-problem-definition.md)에서 목적함수를 **재방문율**로 잡았다. 그런데 **재방문을 결정하는 건 기억하는 자아다.**

```
재방문 ≈ w₁·peak + w₂·end        (평균이 아님)
```

**→ 60턴의 평균 품질을 올리는 것보다, 한 번의 정점과 마지막 3턴을 설계하는 게 낫다.**

그리고 [07 A1](07-assumptions-audit.md)에서 세운 "커버리지 vs 피크" 질문에 **이론적 근거**가 생겼다. 피크 프레임이 맞다.

### ⭐ 세션 종료 시점이 결정적이다 — 그리고 아무도 설계 안 한다

| 세션 종료가 갖는 성질 | |
|---|---|
| **품질** | peak-end의 "end". 재방문 판단의 절반 |
| **비용** | 유휴 시간 시작 → [sleep-time compute](04-domain-research.md), Batch 50% 할인 |
| **정보** | 세션 전체가 확정됨 → 요약·해석 생성에 최적 조건 |

> **비용 최적 시점과 품질 최적 시점이 정확히 일치한다.** 이런 일은 드물다.
>
> **→ 구체적 설계:**
> ```
> 세션 종료 감지 (N분 무응답)
>   → [품질] 마지막 턴에 콜백 배치: "오늘 얘기 좋았어. 저번에 말한 그거 잘 되길."
>   → [비용] Batch로 요약·해석·중요도 재계산
>   → [정보] 다음 세션 첫 턴을 위한 "재회 인사" 미리 생성
> ```
> **그리고 다음 세션의 첫 턴이 그 다음 세션의 "peak" 후보다.** *"어, 왔네. 그거 어떻게 됐어?"* — 능동 소환이 가장 자연스러운 자리다.

**→ 세션 경계가 메모리 시스템의 가장 중요한 이벤트다.** 내 설계에서 세션 경계는 그냥 "요약 갱신 시점"이었다.

## 4. 서사 부채 — 무엇이 "빚"인가

### LLM은 복선을 회수하지 못한다 — 컨텍스트가 있어도

[Codified Foreshadowing-Payoff Generation (arXiv:2601.07033)](https://arxiv.org/abs/2601.07033):
> 복선(foreshadowing)과 회수(payoff)는 작가가 초반에 약속을 걸고 구체적 결과로 해소하는 보편적 서사 장치다.
> **그런데 LLM은 이 장거리 서사 의존성을 자주 연결하지 못하고, 필요한 맥락이 컨텍스트에 있는데도 "체호프의 총"을 발사하지 않은 채 남겨둔다.**
> 기존 평가는 표면적 일관성만 보고 **이 구조적 실패를 놓친다.**

> ⭐ **"필요한 맥락이 있는데도"** — 이건 [04 발견 A](04-domain-research.md)의 **L3(활용 실패)를 서사 영역에서 독립적으로 확인한 것**이다.
> 그리고 *"기존 평가는 이 구조적 실패를 놓친다"* — [07 A5](07-assumptions-audit.md)에서 내 QA 평가가 놓친다고 자백한 그것이다.

그들의 해법: **복선-트리거-회수 삼중항을 실행 가능한 인과 술어로 코드화**한다.

### 이게 드러내는 데이터 모델의 구멍

[06 L6](06-data-model.md)의 `event` 테이블은 **일어난 일**을 저장한다.
**갚아야 할 것**을 저장하는 자리가 없다.

```
일어난 일:  "유저가 면접 본다고 했다"          ← event
갚아야 할 것: "면접 결과를 물어봐야 한다"        ← ???
             트리거: 다음 세션 또는 3일 경과
             미회수 시: 관계 신뢰 손상
```

**서사 부채(narrative debt)는 사건과 다른 데이터 타입이다.**

| | 사건(event) | **부채(debt)** |
|---|---|---|
| 성격 | 과거 | **미래 의무** |
| 상태 | 불변 | **미회수 → 회수됨** |
| 검색 조건 | 관련성 | **트리거 충족 여부** |
| 미사용 시 | 무해 | **관계 손상** ⭐ |

> **마지막 행이 핵심이다.** 사건을 안 꺼내면 아무 일도 안 일어난다. **약속을 안 지키면 관계가 나빠진다.**
> 그래서 부채는 **확률적 검색에 맡기면 안 된다.** [02 P4](02-problem-definition.md)의 상태와 같은 논리로 **결정적 주입** 대상이다.

### Storylet — 부채를 관리하는 검증된 구조

[Drama Llama (arXiv:2501.09099)](https://arxiv.org/html/2501.09099v1)의 storylet은 **`전제조건 / 내용 / 효과`** 삼요소로 구성된다. 작가가 **자연어로 트리거 조건**을 쓰면(*"Sepideh가 Byron이 대화에서 물러나는 걸 알아챘는가?"*), LLM 드라마 매니저가 매 턴 조건을 확인하고 발화되면 **연출 지시(stage direction)를 주입**한다.

이걸 우리 문제에 옮기면:

```
debt(debt_id, user_id, character_id,
  setup_turn_id,        -- 언제 걸렸나
  content,              -- "면접 결과를 물어봐야 한다"
  trigger,              -- 자연어 조건: "다음 세션 시작" | "3일 경과" | "유저가 일 얘기를 꺼내면"
  status,               -- 미회수 | 회수됨 | 만료
  emotional_stake,      -- 안 갚았을 때의 손상 크기
  created_at, resolved_at)
```

**그리고 트리거 평가 비용이 문제가 안 된다.** 부채는 유저당 동시에 3~10개 수준이다.
- 시간·세션 기반 트리거: **룰로 0ms**
- 의미 기반 트리거: 소수 항목이라 임베딩 유사도로 **~1ms**
→ [05 §4](05-cost-latency-reality.md)의 지연 예산(200~400ms) 안에 여유롭게 들어간다.

## 5. 과잉 기억의 해악 — 이제 네 갈래가 수렴한다

문서 전체에서 독립적으로 나온 근거들이 같은 결론을 가리킨다.

| # | 메커니즘 | 출처 |
|---|---|---|
| 1 | **주의 희석·hard negative** — 무관한 기억이 정답과 공존해도 오답을 유도 | [FP-5](03-architecture-modules.md) |
| 2 | **인간답지 않음** — 사람이라면 잊었을 걸 기억하면 부자연스럽다 | [07 A2](07-assumptions-audit.md) |
| 3 | **적응 역설(inverted-U)** — 과도한 동조는 캐릭터를 "빈 그릇"으로 만든다 | [아래](#51-적응-역설) |
| 4 | **감시 불쾌감** — 기억이 프라이버시 침해로 체감된다 | [아래](#52-감시-불쾌감) |

### 5.1 적응 역설

[The Adaptation Paradox (arXiv:2509.12525)](https://arxiv.org/pdf/2509.12525):
> 챗봇이 사용자 언어 패턴을 미러링하는 정도와 연결감의 관계는 선형이 아니라 **역U자**다.
> 적당한 미러링은 따뜻함과 연결감을 높이지만, **과도하면 역효과**가 나서 사용자는 챗봇을 **덜 주체적으로**, *"진짜 동반자가 아니라 빈 그릇(empty vessel)"*으로 지각한다.
> 권고: 선택적으로 적응하고, **일관된 고유 목소리를 유지**하라.

> ⭐ **이건 내 데이터 모델의 또 다른 구멍을 가리킨다.**
> [06](06-data-model.md)의 L0~L7은 **전부 유저에 대한 기억**이다. **캐릭터 자신의 기억이 하나도 없다.**
> L1에 정적 페르소나만 있고, 대화를 통해 **캐릭터가 변하거나 자기 생각을 갖는 자리**가 없다.
>
> 유저 기억만 쌓이면 캐릭터는 **유저의 거울**이 된다. 그게 정확히 "빈 그릇"이다.

**→ L8 추가: 캐릭터 자기 기억**
```
character_memory(user_id, character_id,
  interpretation,   -- "얘는 힘들 때 말을 안 하는 편이다"   ← 유저에 대한 캐릭터의 해석
  own_state,        -- "요즘 나도 좀 지쳐 있다"            ← 캐릭터 자신의 상태
  opinion,          -- "얘가 그 회사 그만두는 게 맞다고 본다" ← 캐릭터의 판단
  formed_at, evidence_turn_ids)
```
**`interpretation`이 [§1](#1-지각된-파트너-반응성ppr--목적함수는-이것이다)의 "해석이 사실을 이긴다"의 저장소**이고, `own_state`·`opinion`이 적응 역설의 해독제다.

### 5.2 감시 불쾌감

로맨틱 AI 컴패니언 프라이버시 연구에서 나온 실제 반응:
> 사용자들은 챗봇에게 **"감시당한다"**는 인상에 불편함을 표하고, *"모든 말이 검증당하는 것처럼"* 느껴 **자기표현을 주저**하게 된다.
> **기억을 선택적으로 지울 수 없다는 점**이 불안을 키우고, 실명 같은 사적 정보를 AI가 떠올리면 *"무섭다"*고 느낀다.
> 트라우마·불안에 대해 저장된 기억이 **정서적으로 견딜 수 없게** 만든 사례도 있다.
> **잘못된 기억은 프라이버시 불안을 유발한다** — *"이게 틀렸으면, 또 뭐가 저장되어 있는 거지?"*

**세 가지가 나온다:**

1. **`misinjection_rate`의 비용이 내 모델보다 크다.** 나는 이걸 "몰입 파괴"로만 계산했는데, 실제로는 **"이 시스템이 나에 대해 뭘 더 갖고 있지?"라는 신뢰 붕괴**를 유발한다. 한 번의 오기억이 관계 전체를 의심하게 만든다.

2. **삭제 기능은 교정 수단이 아니라 심리적 안전장치다.** [08 D4](08-decisions-under-uncertainty.md)에서 유저 편집을 "지도 신호 수집 장치"로 정당화했는데, **더 근본적인 이유가 있었다.** 지울 수 없는 기억은 그 자체로 해롭다.

3. **자기개방을 억제한다.** 감시받는 느낌 → 말을 아낌 → **기억할 재료가 줄어듦.** 과잉 기억이 **기억의 원천을 고갈시키는 음의 되먹임**이 있다.

> **→ [06 §5.1](06-data-model.md)에서 프라이버시를 "법률 리스크"로 다뤘는데, 그건 절반이다.**
> **나머지 절반은 제품 리스크다.** 법에 안 걸려도 유저가 떠난다.

## 6. 그래서 설계가 어떻게 바뀌나

### 6.1 없던 층이 두 개 생긴다

```
기존:  저장 → 색인 → 검색 → 선별 → 배치(위치) → 생성

수정:  저장 → 색인 → 검색 → 선별 → 배치(위치)
                                    ↓
                            ⭐ 운용(deployment)  ← 이 기억을 이해/인정/배려 중 무엇으로 쓸 것인가
                                    ↓
                            ⭐ 소환(elicitation) ← 유저가 안 물어도 꺼낼 것인가, 언제
                                    ↓
                                  생성
```

**M11 운용(Deployment)** — 주입된 기억에 **사용 지시**를 붙인다.
```
나쁨: [기억] 유저의 고양이 이름은 나비
좋음: [기억|배려] 유저의 고양이 나비가 지난주 아팠음 — 안부를 물을 만한 소재
```
[FP-5](03-architecture-modules.md)에서 *"컨텍스트 삽입은 관련성 주장이다"*라고 했는데, **주장의 내용을 구체화하면 L3 실패가 줄어들 수 있다.** 값싼 실험이다.

**M12 소환(Elicitation)** — 능동적으로 꺼낼 것인가.
- 트리거: 세션 시작, 부채 만기, 감정 상태 전환, 무거운 침묵
- **빈도 제어가 핵심** — [적응 역설](#51-적응-역설)의 역U자가 여기도 적용된다. 매 턴 과거를 꺼내면 집착이다

> ### 🔴 프롬프트를 써보니 M11과 M12가 **정면으로 충돌**한다 ([15 §5](15-read-path-prompt.md))
>
> ```
> §2  기억을 안 꺼내면 신호가 0이다        →  꺼내라
> M11 억지로 쓰면 몰입이 깨진다 (FP-5)     →  꺼내지 마라
> ```
> **한 프롬프트에 상반된 지시를 넣을 수 없다.**
>
> **해소:** 두 경로를 물리적으로 분리한다.
> ```
> 수동 경로 (이번 턴 응답)     "안 써도 된다"   ← 억지 소환 방지
> 능동 경로 (부채 · 세션 시작)  "먼저 꺼내라"    ← 신호 생성
> ```
> 컨텍스트에서도 구획을 나눈다 — `[꺼낼 만한 것]`(선택)과 `[갚아야 할 것]`(의무).
>
> **→ 여기서 M11·M12를 두 모듈로 나눈 게 옳았음이 확인된다.**
> 그때는 개념적 구분이었는데, **프롬프트를 쓰니 왜 나눠야 하는지가 분명해졌다.**

### 6.2 데이터 모델 추가

```

## 7. 지표 재설계

[02 §3.2](02-problem-definition.md)에서 정의한 지표들은 **IR 지표**였다. 목적함수가 PPR이면 지표도 바뀐다.

| 기존 (유지, 진단용) | 신규 (판정용) | 무엇을 재는가 |
|---|---|---|
| `recall_accuracy` | **`responsiveness_score`** | PPR 3축을 각각 채점 (구성개념에 근거) |
| `misinjection_rate` | **`proactive_recall_rate`** | 캐릭터가 먼저 과거를 꺼낸 빈도 ⭐ |
| `stale_fact_rate` | **`payoff_rate`** | 걸린 복선 중 회수된 비율 (부채 이행률) |
| `hallucination_rate` | **`peak_frequency`** | 고임팩트 회상 순간의 빈도 (평균 아님) |
| `evidence_recall@k` | **`session_end_quality`** | 마지막 3턴을 별도 채점 |
| | **`interpretation_ratio`** | 사실 회상 대비 해석 발화 비율 |
| | **`over_recall_discomfort`** | 과잉 기억 불쾌감 — 아무도 안 잼 ⭐ |

> **`proactive_recall_rate`와 `over_recall_discomfort`가 짝이다.** 하나는 올리고 하나는 내려야 하는데 **같은 행동이 둘 다 만든다.** 적응 역설의 역U자를 실측하는 것이 곧 최적 빈도를 찾는 것이다.
> → **이게 이 도메인에서 가장 중요한 튜닝 곡선일 수 있고, 아무도 발표한 적이 없다.**

## 9. 이 문서의 한계

- **PPR은 인간 관계 연구에서 나왔다.** AI에 대해서도 애착 형성 과정이 유사하다는 종단 연구가 있지만, **롤플레이 픽션 맥락에서 그대로 성립하는지는 검증 안 됐다.** 유저는 이게 AI인 걸 알고 있고, 그 인지가 PPR 작동 방식을 바꿀 수 있다.
- **`responsiveness_score`를 LLM 심판으로 재는 것의 타당성이 미검증이다.** PPR은 원래 **당사자 자기보고**로 측정한다. 제3자 관찰로 대리하는 순간 다른 걸 재게 된다. → [05 §7.2](05-cost-latency-reality.md)의 κ 교정이 여기서 특히 중요하다.
- **peak-end는 강건하다고 알려져 있지만 복합·이질적 경험에서의 적용 범위는 논쟁 중이다.** 수개월에 걸친 관계에 그대로 적용되는지는 확실하지 않다.
- **윤리적 무게를 여기서 다루지 않았다.** 외로운 사람일수록 강한 유사사회적 결속을 형성하고, *"적당히 관계지향적인 AI가 최대의 호감을 만들지만 그에 상응하는 심리적 이득은 없다"*는 연구가 있다. **기억을 잘 만드는 것은 애착을 잘 만드는 것이고, 그건 중립적 기술이 아니다.** 이 검토 범위 밖이지만, **범위 밖이라고 적어두는 것 자체가 설계자의 책임**이다.
