# ADR-005: 망각과 현저성 — 무엇을 버리고 무엇을 남기는가

- **상태:** 제안됨 (핵심 파라미터는 실험 대기)
- **일자:** 2026-09-03
- **관련:** ADR-002, ADR-006
- **근거 문서:** [03 FP-3](../03-architecture-modules.md), [05 §6](../05-cost-latency-reality.md), [07 A2](../07-assumptions-audit.md), [09 §5](../09-what-memory-is-for.md)

## 맥락

컨텍스트를 상수로 유계하려면 무언가는 버려야 한다. 그런데 **무엇을 버릴지에는 최적해가 존재하지 않는다.**

이 문제는 **캐시 교체 문제와 동형**이다. Belady의 최적 알고리즘(가장 나중에 쓰일 것을 축출)은 미래 접근을 알아야 하므로 온라인에서 구현 불가능하고, 결정론적 온라인 알고리즘의 경쟁비 하한은 캐시 크기 `k`다. **어떤 영리한 정책도 최적 대비 k배 나쁠 수 있다.**

그리고 실제 서비스가 이 문제에서 실패한 사례가 있다. 유사 서비스 A는 기억력을 **개선**한 뒤, 한참 전의 사소한 점심 메뉴를 캐릭터의 유언에까지 끌어왔다는 반응(«빵 유언»)을 얻었다. **회상률을 올렸더니 품질이 떨어졌다.**

## 결정 동인

1. 현저성 판단 정확도 (중요한 것을 남기기)
2. **오주입 억제** — 이 도메인에서는 recall 실패보다 precision 실패가 비싸다
3. 판단 비용이 응답 경로에 오지 않을 것
4. 잘못된 판단을 되돌릴 수 있을 것

## 고려한 선택지

1. **전부 보관 + 시간 감쇠만** — 단순, 의미 신호 없음
2. **LLM importance 스코어링** — Generative Agents 방식
3. **에빙하우스 곡선 (인간 기억 모사)** — MemoryBank 방식
4. **Rate-distortion 최적화** — 이론적으로 정확, 지도 신호 필요

## 결정

> **우리는 2번을 기본으로 하되, 3번의 문제의식을 실험 가설로 남긴다.**
> **그리고 가장 중요한 결정: 망각은 "저장에서 지우는 것"이 아니라 "주입에서 빼는 것"이다.**

```
저장(L0 원본)    : 절대 안 지움 — 삭제는 법률 결정 (ADR-010)
색인             : 의례적 발화·민감 범주는 제외
주입             : 여기서 버린다 — 스코어링 + 임계 컷
```

**주입 스코어 — 🔄 [11 실험 C](../11-experiment-results.md) 실측으로 수정됨:** 🔄 *프로토타입은 이 5항이 아니라 3항이다 — 아래 «미해결».*
```
1단계  색인 선별   : 의례적 발화·민감 범주는 애초에 색인하지 않는다
2단계  하드 게이트 : if importance < τ (≈0.2): 후보에서 제외      ← ⭐ 추가
3단계  가중 정렬   : score = w_rel·relevance
                          + w_imp·importance
                          + w_emo·emotional_weight
                          − w_rec·recency_penalty
                          − w_rep·surfaced_penalty
4단계  임계 컷     : score < θ 인 것은 넣지 않는다 (0개 반환 허용)
```

> **원래 이 ADR은 3단계(가중합)만 있었다. 실측에서 그것만으로는 부족했다.**
> importance 0.05짜리 사소한 기억이 relevance 최댓값을 받으면, **곱하든 더하든 상위에 남는다.**
> ```
> 곱셈  rel × imp    → 트랩 2위  ❌
> 덧셈  rel + imp    → 트랩 2위  ❌
> 하드필터 imp<0.2 제외 → 트랩 20위 ✅
> ```
> **→ 현저성은 순위 조정이 아니라 자격 심사여야 한다.**
> [Generative Agents](https://ar5iv.labs.arxiv.org/html/2304.03442)의 3항 가중합을 그대로 가져온 게 실수였다. 그건 에이전트 시뮬레이션용이고, **오주입 비용이 비대칭인 우리 도메인에는 안 맞는다.**
>
> ⚠️ 하드 게이트의 대가: **importance는 낮지만 지금 딱 맞는 기억**을 영구히 못 꺼낸다.
>
> **✅ τ 실측 완료** ([11 실험 7A](../11-experiment-results.md))
> ```
> τ = 0.0        노이즈 1.38/질의   ← 게이트 없음
> τ = 0.15~0.4   노이즈 1.12~1.23   ← 사실상 평평
> τ = 0.5        recall 96% → 93%   ← 여기서 깨진다
> ```
> **결론: τ는 0.2~0.4 어디든 괜찮고, 0.5는 넘지 마라.**
> *"최적값 0.3"*이라고 쓰면 과적합이다. **파라미터가 둔감하다는 게 결론**이고, 튜닝에 시간을 안 써도 된다는 뜻이라 좋은 소식이다.
> 그리고 τ=0 대비 노이즈가 19% 줄므로 **게이트 자체는 값을 한다.**

## 근거

**왜 저장/주입을 분리하는가:** 저장 비용은 유저당 월 $0.00005, 주입 비용은 $10~25. **50만 배 차이**다. 그러므로 *"저장할까?"의 기본값은 예스, "주입할까?"의 기본값은 노*여야 한다. 이 둘을 "메모리"라는 한 단어로 부르는 것이 판단을 흐린다.

**왜 importance를 쓰기 시점에 계산하는가:** 읽기 시점 계산은 지연 예산 200~400ms를 먹는다. 쓰기 시점이면 Batch 50% 할인까지 받는다. *"점심에 빵 먹음"*에 `importance=0.1`이 붙어 있으면 relevance가 높아도 총점에서 밀린다 — 유사 서비스 A 사례에 직접 대응한다.

**왜 `emotional_weight`가 별도인가:** 롤플레이의 현저성은 사실 중요도가 아니다. 이직 실패보다 사소한 다툼이 더 중요할 수 있다.

**왜 "최적 망각률 > 0"을 가설로 두는가 — 네 갈래가 수렴한다:**

| # | 메커니즘 |
|---|---|
| 1 | **주의 희석** — 무관한 기억이 정답과 공존해도 오답을 유도(hard negative). 입력 길이 자체도 성능을 떨어뜨린다 |
| 2 | **인간답지 않음** — 3년 전 대화를 토씨까지 인용하는 상대는 친밀한 게 아니라 섬뜩하다 |
| 3 | **적응 역설** — 과도한 동조는 캐릭터를 "빈 그릇"으로 만든다 (역U자) |
| 4 | **감시 불쾌감** — 기억이 프라이버시 침해로 체감되어 **자기표현을 억제**한다 |

4번은 특히 위험하다. **자기표현이 줄면 기억할 재료 자체가 고갈되는 음의 되먹임**이 생긴다.

**Rate-distortion 관점의 보정:** 망각은 캐시 교체와 동형이지만 결정적 차이가 있다 — 캐시의 distortion은 **이진**(히트/미스)이고 메모리는 **연속**("얼마나 나쁜 답을 하는가")이다. 부분 정보(요약본)가 유의미하고 다른 기억으로 대체도 가능하다. **그래서 LRU 유추는 거기까지고**, 망각은 "버릴까 말까"가 아니라 **"얼마나 압축할까"**라는 연속 결정이다.

## 결과

**좋아지는 것**
- 잘못 버린 판단이 되돌릴 수 있다 (원문이 남아 있으므로)
- 판단 비용이 응답 경로에 전혀 오지 않는다

**감수하는 것**
- **최적을 추구하지 않는다.** 이론적으로 불가능하므로, 대신 **oracle과의 격차를 측정**한다 — 실험에 `A1 Oracle` arm이 있는 이유가 이것이다
- importance 추출이 틀리면 그 기억은 사실상 사라진다 (원문엔 있지만 안 꺼내짐)

**새로 생기는 장애 지점**
- 가중치 5개가 튜닝 대상이다. 잘못 잡으면 조용히 품질이 떨어진다 → **provenance 로깅으로 사후 추적 가능하게 한다**(ADR-004)

## 재검토 트리거

- **실험에서 "흐릿한 회상"이 "정확한 회상"보다 자연스럽다는 결과가 나오면** → 3번(에빙하우스)으로 전환
- 유저 편집 데이터가 충분히 쌓이면 → 그것이 효용 지도 신호가 되므로 4번(rate-distortion) 검토 가능
- oracle 격차가 5%p 미만이면 → 스코어링을 더 정교하게 할 이유가 없다. 단순화
