# ADR-009: 평가 설계 — 무엇을 어떻게 재는가

- **상태:** 제안됨
- **일자:** 2026-09-03
- **관련:** 전체
- **근거 문서:** [01 §4~5](../01-problem-and-hypotheses.md), [05 §7.2](../05-cost-latency-reality.md), [07 A5·A6](../07-assumptions-audit.md), [09 §7](../09-what-memory-is-for.md)

## 맥락

메모리 시스템의 우열을 어떻게 판정할 것인가. 이 결정이 나머지 모든 ADR의 근거를 만든다. **평가가 틀리면 나머지가 전부 틀린다.**

그리고 이 분야의 평가에는 알려진 함정이 있다. 통제 baseline 없이 낸 결론은 신뢰할 수 없고, 공개 벤치마크 점수는 대부분 자가 보고이며 서로 반박 중이다.

## 결정 동인

1. 실제 실패 양상과의 일치
2. 재현 가능성 / 통제
3. 짧은 기간 안에 실행 가능
4. 결론의 정직한 범위 표시

## 결정

> **① 주 판정 지표는 QA 정확도가 아니라 PPR·사고율·피크 빈도다. QA는 진단용으로 강등한다.**
> **② 통제 baseline 5종을 항상 함께 돌린다.**
> **③ 동일 토큰 예산·동일 모델·동일 시드로 통제한다.**
> **④ 심판은 생성 모델과 다른 벤더로 두고, 위치 무작위화 + κ 표본 교정을 한다.**
> **⑤ 결론을 "상대 순위"로 한정한다고 리포트에 명시한다.**

## 근거

### ① 왜 QA를 주 지표에서 내리는가

나는 *"LongMemEval은 영어 어시스턴트 도메인이라 그대로 쓴 결론은 설득력이 약하다"*고 쓴 뒤, **도메인만 바꾸고 형식은 그대로 베낀 QA 세트를 만들었다.**

**롤플레이에서 아무도 퀴즈를 내지 않는다.** *"내 고양이 이름 뭐였지?"*라고 묻는 유저는 시스템을 테스트하는 유저지 즐기는 유저가 아니다.

| 유저가 실제로 겪는 것 | QA가 재는 것 |
|---|---|
| *"갑자기 캐릭터가 이상해졌다"* | 정답을 맞췄는가 |
| *"몰입이 깨졌다"* | 사실 회상 정확도 |
| *"같은 말 반복한다"* | (측정 안 함) |

**주 지표 (판정용)**
```
responsiveness_score    PPR 3축(이해·인정·배려)을 각각 채점
proactive_recall_rate   캐릭터가 먼저 과거를 꺼낸 빈도
over_recall_discomfort  과잉 기억 불쾌감
misinjection_rate       무관한 기억 주입률
persona_adherence       PersonaGym 5축 차용
payoff_rate             걸린 복선 중 회수된 비율
session_end_quality     마지막 3턴 별도 채점
peak_frequency          고임팩트 회상의 빈도 (평균 아님)
```

**진단 지표 (원인 규명용)**
```
recall_accuracy (유형별), stale_fact_rate, hallucination_rate,
evidence_recall@k, memory_repetition, state_violation_rate
```

**왜 `peak_frequency`가 평균이 아닌가:** 재방문을 결정하는 건 **기억하는 자아**이고, 기억된 효용은 **정점과 종점의 가중평균**이지 전체 평균이 아니다. 엔터테인먼트는 평균 품질 사업이 아니라 피크 경험 사업이다.

**`proactive_recall_rate`와 `over_recall_discomfort`가 짝이다.** 하나는 올리고 하나는 내려야 하는데 **같은 행동이 둘 다 만든다.** 적응 역설의 역U자를 실측하는 것이 곧 최적 소환 빈도를 찾는 것이다. **이 곡선은 아무도 발표한 적이 없다.**

### ② 통제 baseline — 없으면 결론이 무의미하다

| ID | arm | 역할 |
|---|---|---|
| `A0` | Full-context | 정확도 상한 |
| **`A1`** | **Oracle 검색** | **이론적 상한 + L3(활용) 실패 격리** ⭐ |
| `A2` | Window-only | 지연·비용 하한 |
| **`A3`** | **Random-K** | **위생 검사 — 못 이기면 검색이 작동 안 함** |
| `G1` | 현행 구조 재현 | 대조군 |

**`A1`의 역할이 특히 중요하다.** 정답 근거를 확실히 넣어줬는데도 틀리면, 그건 저장 실패도 검색 실패도 아닌 **활용 실패(L3)**다.

이 구분은 실증적 근거가 있다 — 유사 서비스 A 유저들은 답변을 재생성하면 대부분 다시 기억한다고 보고한다. **재생성은 컨텍스트를 바꾸지 않는다.** 정보는 이미 있었고 생성이 실패한 것이다. 서사 영역에서도 같은 현상이 확인된다 — LLM은 *"필요한 맥락이 컨텍스트에 있는데도 체호프의 총을 발사하지 않는다."*

```
L1 저장 실패 : 아예 안 남김
L2 검색 실패 : 남겼는데 못 찾음
L3 활용 실패 : 넣었는데 안 씀      ← 거의 모든 벤치마크가 안 잼
```

> **→ 실험 순서: `A1`을 가장 먼저 돌려 L3 실패율을 잰다.**
> L3가 크면 메모리 구조 개선의 상한이 낮으므로 배치·프롬프트 실험을 앞으로 당기고, 작으면 원래 계획대로 간다. **arm 하나, 문항 60개짜리 값싼 측정이 남은 실험 전체의 방향을 정한다.**

### ③ 통제 조건

| 변수 | 고정 |
|---|---|
| 컨텍스트 토큰 예산 | **4,000 (전 arm 동일, `A0` 제외)** |
| 생성 모델 / temperature / seed | 동일 |
| 최근 턴 수 | 동일 |
| 반복 | arm·문항당 3회, 평균 + 표준편차 — 🔄 *실측은 1회였다(아래 «미해결»)* |

**동일 토큰 예산이 전부다.** 예산을 안 맞추면 *"더 많이 넣은 쪽이 이겼다"*는 자명한 결과만 나온다.

### ④ 심판 편향 통제

- **자기 선호**: LLM 심판은 자기 생성물을 알아보고 선호하며, 자기인식 능력과 선호 강도가 선형 상관한다 → **생성과 다른 벤더로**
- **위치 편향**: 심판 모델 선택이 가장 큰 요인 → **A/B 위치 무작위화 + 순서 뒤집어 재평가**
- **교정**: 태스크마다 인간 라벨로 경험적 교정 필요 (κ > 0.6 수용) → **표본 20~30건**
- arm에 대해 **블라인드**

⚠️ **PPR은 원래 당사자 자기보고로 측정한다.** 제3자 관찰(LLM 심판)로 대리하는 순간 다른 걸 재게 된다. 이 한계를 리포트에 명시한다.

### ⑤ 데이터셋과 그 한계

**자체 한국어 롤플레이 코퍼스**를 주(主)로 쓴다. LoCoMo는 2026년 기준 너무 짧아 변별력이 없고, LongMemEval은 영어 어시스턴트 대화다. `longmemeval_s` 100문항 서브셋은 **하네스 sanity check용**으로만 병행한다.

**역방향 생성:** 사실 대장(fact ledger)을 먼저 설계하고 *"F001을 3세션 12턴에서 자연스럽게 언급하는 대화를 써라"*로 생성한다. 근거 위치가 정확히 알려지므로 `A1 Oracle`과 유형별 채점이 가능해진다.

의도적으로 심는 것: **빵 함정**(사소한 사건 + 감정 어휘 근처), 지식 갱신, abstention 표적(한 번도 언급 안 된 주제), 서사 부채, 노이즈 60% 이상.

> ⚠️ **순환성을 인정한다.** LLM이 쓴 대화로 LLM 메모리를 테스트한다. 합성 대화는 실제 유저 대화보다 더 명시적이고 일관되고 **추출하기 쉽다.** 실제 유저는 파편·오타·이모지·번복을 쓴다.
> **→ 결론을 "상대 순위"로 한정한다. 절대 성능은 예측할 수 없다고 명시한다.** 완화책으로 노이즈를 의도적으로 섞는다.

## 결과

**좋아지는 것**
- 실제 실패 양상에 가까운 것을 잰다
- L1/L2/L3 계층 진단이 가능해 개선 투자처가 명확해진다

**감수하는 것**
- 신규 지표 7개는 선례가 없어 **타당성이 미검증**이다
- 짧은 기간 안에 완전한 인간 교정은 불가능하다 → **표본만 했다고 명시**
- 최종 지표(재방문율)는 못 잰다 → **대리 지표임을 명시**

## 재검토 트리거

- 신규 지표들이 서로 강하게 상관하면 → 중복. 축소
- `responsiveness_score`가 인간 라벨과 κ < 0.4면 → 지표 폐기 또는 재설계
- 실제 유저 로그 확보 시 → 합성 코퍼스 결론을 전면 재검증

## 미해결

> 🔄 **2026-09-10 괴리 처분이 이 절을 만들었다** ([docs/17](../17-gap-disposition.md) 검기타-6 · R18 · 밖E11). 상태 «제안됨»과 위 결정은 그대로 두고, **실측이 위 ③·⑤를 지키지 못한 자리**를 적는다.

- **③ 통제 조건 — 코드로 확인한 둘.** ① 반복: `quality_run.py`의 `--repeat` 기본값이 **1**이고 응답 품질(실험 13)은 1회 실행의 값이다. 반복은 실험 14가 분산을 재려고 따로 했다 ② seed: Gemini 요청(`generationConfig`)에 **seed가 없고** temperature는 0.7이다 — temperature는 arm 사이에 같지만 같은 입력도 실행마다 다른 답을 낸다(실험 14). ❔ 연구 문서가 함께 적은 셋(예산 4,000이 arm별로 다름 · κ 교정 0건 · Random-K가 검색 시뮬에만)은 **이 절이 확인하지 않았다.** 🔄 *그 셋을 코드로 확인했다 — 이 절 끝 «통제 조건 감사» 항목.*
- **⑤ 코퍼스 — 역방향 «LLM 생성»이 아니라 규칙 생성이다.** `experiments/gen_corpus.py`는 대장에서 템플릿으로 720턴을 만든다(그 파일 머리: «좋은 산문이 필요 없다 … 품질 평가용 코퍼스는 LLM 생성이 필요하다»). [docs/11](../11-experiment-results.md)이 «응답 품질 평가에는 못 쓴다»고 적었는데, 응답 수준 실험들은 그 코퍼스 위에서 쟀다.
- **다시 잴 길은 저장소 밖에 있다.** Gemini 쪽은 비로컬 전송 금지로 다시 못 돌리고, 로컬 쪽은 **temperature 0이 재현을 주지 않는다**(F39 — [docs/12](../12-objections.md) §3), 다른 벤더 심판은 U2다. 그래서 «통제 조건을 지켜 다시 잰다»(docs/17 밖E11)는 ⏸이고 docs/12 §3에 사례로 올렸다.
- 🔄 **통제 조건 감사 — 2026-09-10 레인 B가 코드와 조립 출력으로 확인했다** (`experiments/eval_controls_audit.py` · LLM 0회 · DB는 `%TEMP%`). 요구 목록은 위 ②·③·④ 본문에서 뽑는다(arm 5종 · 예산 4,000 · 반복 3회 · κ 표본 20~30건 — 못 뽑으면 감사가 멈춘다). 대상은 실험 13의 하니스 `quality_run.py`와 `experiments/*.py` 전체다.
  - **예산 4,000 전 arm 동일 — 위반. 정확히는 «arm별로 다르다»가 아니라 예산이라는 변수가 없다.** 주석·문자열을 뺀 코드 토큰에 `4000`도 `budget`도 0곳이다. 26문항을 조립해 재면 A0 계열을 뺀 네 arm의 프롬프트 글자수 중앙값이 A1 310.5 · G1 662.5 · A2 809.5 · C 863으로 **2.78배** 벌어진다(글자 기준 — Gemini 토크나이저는 안 쟀으므로 비만 판정한다).
  - **A3 Random-K는 검색 시뮬에만 — 참.** 무작위 arm 이름(`Random-K`·`arm_random`·`random_k`)이 `arms_sim.py`에만 있고, LLM 생성을 부르는 파일 10개와 교집합이 0이다. 그래서 baseline 5종도 **위반** — `build_arms`의 arm은 A0·A0R·A1·A2·C·G1이다.
  - **κ 교정 0건 — 참. 다만 이유가 «안 했다»보다 앞에 있다: 교정할 LLM 심판이 없다.** 코드 토큰에 `kappa`·`cohen`·`fleiss` 0곳(언급은 `probe_set.py` 두 줄 — «하지 않았다»). 응답 수준 채점은 규칙(`quality_run.score`)이거나 사람 판정이고, 사람 라벨(`LABELS_HUMAN2.json`·`LABELS_HUMAN3.json`)은 **규칙 채점기의 정확도** 검증(`scorer_eval.py`)이지 심판 κ가 아니다. 그래서 ④는 지금 «어긴 조건»이 아니라 **심판이 생기는 순간 걸리는 조건**이다.
  - 같은 감사가 본 나머지: 최근 턴 수 동일 — **위반**(A1 0 · C 9 · G1 10 · A2 30줄) · temperature 동일 — 충족(모든 arm이 `generate` 하나를 부른다) · seed — 위반 · 반복 3회 — 위반(위 첫 항목과 같다).
  - 감사는 이 상태를 `KNOWN`으로 들고 **다르면 종료 1**이다 — 새 위반도, 고쳐진 위반도 운다. 복사본에 seed·반복 3·생성 파일의 Random-K arm을 심으면 셋 다 종료 1, 주석에 적은 seed·예산은 종료 0(조용한 쪽)을 확인했다. 🔓 **열리는 조건:** 이 감사가 종료 1을 내는 순간. ⚠️ `run_all`에는 올리지 않았다(이 레인 소관 밖).
