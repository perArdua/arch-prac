## 맥락

**요약은 실험 스크립트에만 있었다.** 프로덕션 코드에 요약을 **만드는** 경로가 한 줄도 없었고, `digest` 테이블은 `build_context`가 **읽기만** 했다. 요약을 쓰는 `INSERT`는 전부 데모·실험 파일(`demo.py` · `deletion_demo.py` · `quality_run.py` · `fsm_probe.py`)에 있었다.

🔴 **그리고 [ADR-013](ADR-013-summary-regeneration.md)의 채택 결정 P4가 현행 스키마에서 실행 불가능했다.**
ADR-013의 결정은 *"lifetime 요약은 **모든 세션 요약**에서 다시 쓴다"*이고, 그 선택지 표는 P4의 사슬 깊이를 **2**로, 기각한 P2(증분)를 **400**으로 적었다.
그런데 `digest`의 PK는 `(chat_id, kind)`다 — **세션 요약은 채팅당 1행이다.** "모든 세션 요약"이라는 입력 집합의 크기가 **1**이었다.

> **현행 스키마가 지원하는 유일한 재작성 방식은 ADR-013이 기각한 P2였다.**
> 그래서 "N세션 보존"은 취향이 아니라 **채택된 ADR을 실행 가능하게 만드는 최소 조건**이다.

### 선행 실측 — 6방식 재채점표

`.omc/plans/baseline/after-r2a/summary_v2_recomputed.txt`(qwen3:8b · 세션 12개 · 모델 재호출 0회).
**두 열의 분모가 다르다 — 표 제목에 박는다.** `frozen`은 대장 항목 11개 전부를, `v2`는 어근 2개 미만 항목 1개를 판정 불가로 뺀 10개를 채점한다. **두 열을 빼지 않는다.**

| 방식 | 생존(frozen, **/11**) | 생존(v2, **/10** + 판정 불가 1) | 거친 단계 |
|---|---|---|---|
| 세션 요약 (전체 합침) | 8/11 | **6/10** | 1 |
| 2층 · 기본 지시 | 2/11 | **2/10** | 2 |
| 2층 · 사실 우선 | 4/11 | **2/10** | 2 |
| 2층 · 밀도 올리기 1회 | 3/11 | **2/10** | 2 |
| 2층 · 밀도 올리기 2회 | 3/11 | **2/10** | 2 |
| 3층 · 세션→구간→전체 | **0/11** | **0/10** | 3 |
| 증분 · 깊이가 12까지 자람 | 2/11 | **1/10** | 12 |

🔴 **이 표의 항목 집합은 `facts`가 아니다.** S01–S12 구간의 **사실 8 + 사건 3 = 혼합 11개**이고, 판정 불가 1을 빼면 10이다. 아래 §결과의 «M2 상한 대조군»의 `x/10`(사건 10개)과 **모양만 같고 집합이 다르다.**

### ⭐ 이 표가 준 것 셋

**⭐ 핵심 1 — 깊이가 범인이 아니다.** 깊이 2(2/10)와 깊이 12(1/10)가 사실상 같고, 두 채점 모두에서 **0인 것은 3층 하나**다. 범인은 사슬이 길어지는 것이 아니라 **새 재료 없이 한 번 더 재압축하는 것**이다.

**⭐ 핵심 2 — `survived()`는 요약의 일이 아닌 것을 잰다.** [`docs/14`의 P4 규칙](../14-extraction-prompts.md)이 *"구체적 사실(이름·직업·체질·가족)은 여기서 다루지 않는다. 사실 계층이 담당한다"*라고 **명시**하는데, 실험 19·20은 대장 **사실** 생존율로 요약을 채점했다. 지표를 안 바꾸면 다음 라운드도 *"요약이 사실을 못 담는다"*를 세 번째로 발견하고 끝난다.

**⭐ 핵심 3 — 요약 계층은 시간순 세그먼트 트리다.** 세션 요약이 잎이고 lifetime이 뿌리이며, 각 노드는 **자기 구간(`covers_from_seq`–`covers_to_seq`)을 덮는다.** ADR-013이 «깊이 2»라 부른 것이 이 트리의 높이이고, 3층은 중간 노드를 한 층 더 놓는 것이다. **그래서 3층 기각(핵심 1)과 «구간을 저장한다»(§결정)가 같은 그림의 두 면이다** — 노드가 자기 구간을 모르면 재생성이 무엇을 덮는지 아무도 모른다.

## 결정

### ① 저장 — `digest_session` (스키마 v5 측면 테이블)

```sql
CREATE TABLE IF NOT EXISTS digest_session (
  chat_id TEXT, kind TEXT, content TEXT,
  covers_from_seq INTEGER, covers_to_seq INTEGER,
  session_end_note TEXT, generated_at REAL,
  PRIMARY KEY (chat_id, kind));
```

`SCHEMA_VERSION = 5` · `MIGRATIONS[5] = []`(빈 리스트는 «잊었다»가 아니라 **결정**이다 — 새 테이블은 `SCHEMA`의 `IF NOT EXISTS`가 만든다). **동결 테이블 14개에 컬럼을 하나도 더하지 않았다.**

### ② 🔴 N · M · K · E는 서로 다른 넷이다

| 이름 | 무엇을 세나 (**단위**) | 값 | 무엇이 이 값을 모나 |
|---|---|---|---|
| **N** `DIGEST_KEEP_SESSIONS` | `digest_session`에 **저장**하는 **행 수** | **24** | 코퍼스가 24세션(`eval/fact-ledger.yaml`의 `meta.sessions`). 🔴 **토큰은 이 값을 구속하지 않는다** — 아래 §결과의 저울을 보면 예산이 구속하려면 N ≈ 76이어야 한다 |
| **M** `DIGEST_INJECT_MAX` | 매 턴 **주입**하는 **블록 수** | **1** | 매 턴 토큰 비용(D3). M=1이 **오늘의 컨텍스트 모양과 같다** |
| **K** | `rewrite_lifetime`의 **입력 세션 요약 수** | **= N (전량)** | ADR-013 P4 그대로. 이것이 «깊이 2»의 정의다 |
| **E** `STALE_EXPIRE_SESSIONS` | `stale_expired` 판정의 **세션 경계 수(시간)** | **3** | *"낡은 요약을 언제까지 내보내나"* |

> 🔴 **N(=24)과 E(=3)는 같은 수여야 할 이유가 없다.** N은 행 수를, E는 경계 수를 센다. E를 저장 N으로 옮겨 적으면 세션 요약을 3개만 보관하게 되고 **ADR-013 P4가 다시 실행 불가능해진다.** `prototype/tests/test_migrate.py`의 `test_keep_and_expire_are_not_the_same_number`가 그 실수에 발화한다.

**`lifetime`은 `digest`에 그대로 있다.** 그리고 **`digest.kind='session'`에는 v5부터 쓰지 않는다** — 기존 행은 읽기만 하고 남긴다(아래 §미해결 U11이 그 대가를 진다).

### ③ 서빙 — stale 사유별 3분기

| stale 사유 | 처분 | provenance |
|---|---|---|
| `…삭제됨` / `…무효화됨` | **제외** | `stale` 🔄 *(w33k · 2026-09-12 · 마감 K · Fable 계획 2 «고치지 않을 것»)* **서빙 후보를 고르는 조회(최신 M개 세션 요약)는 stale을 모른다** — 고른 뒤 이 행이 거른다. 그래서 최신 세션이 stale인 동안(삭제 · 재생성 실패 · 🆕 첫 요약이 실패해 남은 표지 행 — 결정 Q8 (a)) 세션 블록이 빈다(M = 1 · 오늘의 재생성 실패와 같은 동작). 후보 선택을 stale 표에 걸면 새 결합이고 전이 측정의 제외 수가 움직여서 안 바꾼다. lifetime 재료 쪽의 같은 구멍은 K1 헬퍼(재료에서 stale 세션 제외 · w20a)가 메운다 · 표지 행이 서빙에 안 나오는 것은 끝-끝 9 · 10단계가 본다(`prototype/tests/test_e2e_deletion_roundtrip.py`) |

🔴 **비대칭이 원칙적인 이유:** **삭제에는 반대 블록이 없고 전이에는 있다.** 사실이 지워졌는데 낡은 요약이 그 사실을 말하면 컨텍스트 안에 그것을 반박할 것이 없다. 반면 관계 stage가 바뀐 경우에는 `build_context`가 **현재 stage를 결정적으로 주입**하므로, 낡은 요약이 옛 stage를 말해도 같은 컨텍스트 안에 최신 값이 함께 있다. 경고를 provenance가 아니라 **블록 본문 안**에 넣는 것도 같은 이유다 — provenance는 모델이 절대 못 본다.

### ④ 생성 — `prototype/summarize.py` · `prototype/regen_job.py`

- `session_digest()` — 그 세션의 **원본 턴**에서 요약 1건. **자기가 덮는 구간을 저장한다**(⭐핵심 3). 재생성은 저장된 구간을 **그대로 다시 쓴다** — 추측하면 그 요약이 무엇을 덮는지 아무도 모르게 된다.
- `rewrite_lifetime()` — **세션 요약 전량만** 읽는다(K = N). 본문에 원본 턴 접근이 없는 것이 P4의 계약이고, `prototype/tests/test_summarize.py`가 **실행되는 SQL을 감시해서** 그것을 지킨다.
- `regenerate_stale()` — **세션 → lifetime 순.** 순서가 임의가 아니다: 세션을 먼저 안 고치면 lifetime은 **낡은 재료로 만든 새 요약**이 된다.
- `regen_job.run()` — 세션 경계 호출자. `soak.py`는 **한 글자도 안 고쳤다**(고치면 soak이 ollama 의존이 되어 완주 게이트의 성격이 바뀐다).

### ⑥ 행 수 상한을 이름 있는 하나로 — G19′

**금지하는 대신 늘어나는 자리 전부를 하나의 이름 있는 상한 아래 넣었다:** `digest` 키 공간의 기수 = `lifetime` 1 + legacy `session` 1 + `session:S01..SN` N = **N+2 = 26**. `experiments/digest_budget.py`가 이것을 **종료 코드로 집행**하고 `run_all.STEPS`에 등록되어 있다. 🔄 *(w16 · w20b · 2026-09-12) «늘어나는 자리 전부»에 `derivation`이 빠져 있었다 — N 상한에 밀려난 세션 키의 파생 행이 남아, 그 세션의 옛 사실을 지우면 이미 없는 키가 stale이 되고 `regenerate_stale`이 경계마다 `regen_failed`를 남겼다(Fable 검토 발견 4 · 재현 R4). 수리: `memory.py` 끝 헬퍼 `_forget_digest_key`가 밀려난 키의 stale · digest_meta · derivation을 함께 지운다(이 키가 파생물인 행만) · 시험 `prototype/tests/test_digest_cap.py` · 변이 발화 · 다른 모델 재검증 ✅. 집행(`digest_budget`의 G19′)은 아직 `derivation`을 세지 않는다 — [docs/17](../17-gap-disposition.md) §18*

### 🟢 재는 것 — 서빙 델타 (단계 S3이 귀속시킨다)

`PYTHONIOENCODING=utf-8 python -B experiments/fsm_probe.py` 절 4-b의 출력:

| `STALE_SERVE_POLICY` | 주입 | 제외 | 경고 주입 |
|---|---|---|---|
| `exclude_all` (= 옛 동작) | **0** | **10** | 0 |
| `transition_warn` (= 새 기본값) | **10** | **0** | **10** |

**🔴 델타: 주입 0회 → 10회 (+10) · 제외 10회 → 0회 (−10).**

- **분모(G15):** `fsm_probe.py`가 심는 digest **2행**(`lifetime` · `session`) × 대장 관계 전이 **5회** = **10**.
- **귀속:** 바꾼 것은 전역 `STALE_SERVE_POLICY` 하나다. 코퍼스·대장·심은 행·전이 수가 두 실행에서 같다.
- **대조:** [ADR-013](ADR-013-summary-regeneration.md)의 미해결에 기록된 **«주입 0회 / 제외 10회»**가 `exclude_all` 쪽에서 그대로 재현됐다. 🔴 **재현됐기 때문에 델타를 귀속시킬 수 있다** — 같은 분모다. `fsm_probe.py`는 그 값을 코드에 안 박고 **ADR-013 파일에서 정규식으로 읽으며**, 못 읽거나 안 맞으면 **종료 1**을 낸다. 🔄 *wave3:* 이 판정은 이제 **옛 전파(`TRANSITION_PROPAGATES_DIGEST = True`)를 이름으로 켜고** 재는 값이다 — 기본값에서는 전이가 digest를 stale로 안 밀어 두 정책이 가를 것이 없다(0 / 0 / 0 · 서빙된 digest 블록 10). 판정 수치는 한 칸도 안 움직였다(U13 · ADR-013 끝 절).
- ⛔ **«0→N회»라 쓰지 않는다.** `N`은 `DIGEST_KEEP_SESSIONS = 24`에 예약된 이름이고 이 델타는 **10**이다. 24와 아무 관계가 없다. *(자기가 예약한 이름을 다른 수에 쓰는 것 — 그것이 위 F12·F19·F21·F38의 축소판이다.)*
- ⚠️ **이것은 서빙 동작의 델타이지 요약 품질의 수가 아니다.** *"낡은 요약이 경고와 함께 나가는 것이 더 낫다"*는 근거는 이 표에 **없다.** 이 표가 말하는 것은 *"정책이 실제로 붙었고 그 크기가 이만큼"*이다.

### 🟢 재는 것 — N=0이면 현행과 동일 (바이트 동일 대조)

`digest_session`이 비면 서빙되는 블록은 오늘과 같다. `precision.py`는 **바이트 동일**이고, soak은 **DB 크기 두 줄을 빼고** 동일하다 — 블록·회상·게이트·`ctx.tokens`가 전부 불변이다.
🔄 **그 두 줄은 «움직였다»로 남긴다:** `턴당 290B → 302B`(월 85KB → 88KB). 원인이 완전히 귀속됐다 — **빈 SQLite 테이블은 0바이트가 아니다.** 테이블 루트 페이지 1 + PK 인덱스 루트 페이지 1 = **페이지 2개 = 8,192B**. 행은 0이고 동작은 한 줄도 안 움직였다.

### 🔴 정직 — 여덟 가지

### 🔄 후속 갱신 — **선택지 K(임베딩 채점)는 실측으로 기각됐다** (실험 26 · 채점기 검증)
