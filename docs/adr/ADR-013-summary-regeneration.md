# ADR-013: 요약 재작성 — 무엇을 입력으로 다시 쓰는가

- **상태:** 채택 (비용 근거만 — **품질 근거는 실측 후 철회**)
- **일자:** 2026-09-07
- **관련:** ADR-002, ADR-008, ADR-011
- **근거 문서:** [06 L4](../06-data-model.md), [실험 15](../11-experiment-results.md)

## 맥락

[06 L4](../06-data-model.md)에서 요약을 2층(`session`·`lifetime`)으로 정하고, 갱신 방식을 **"전체 재작성"**이라고 썼다.
이유는 *"요약의 요약으로 인한 열화(drift)가 없다"*였다.

**그런데 무엇을 입력으로 재작성하는지를 안 정했다.** 두 해석이 갈린다.

```
원본 전체를 읽어 재작성    드리프트 없음 · 세션마다 O(N) → 누적 O(N²)
이전 요약 + 새 세션        O(1) · 그런데 그게 바로 "요약의 요약"
```

**피하겠다고 한 것과 비용이 정면충돌한다.**

## 🔴 그리고 이 검토의 실험 범위가 이걸 가렸다

원래 질문은 *"아주 오랫동안 대화하더라도"*로 시작하는데, **모든 실험이 720턴(24세션)에서 끝난다.**
[04](../04-domain-research.md)의 공개 운영 사례 수치(월 수십 시간 체류)로는 1년 헤비 유저가 **10,000턴 이상**이다.

| 세션 | 턴 | 원본 재작성 | 증분 | 차이 |
|---|---|---|---|---|
| **24** | 1,200 | $1.43 | $0.03 | **안 보임** |
| 100 | 5,000 | $23.77 | $0.12 | 198배 |
| **400** | 20,000 | **$376** | $0.49 | **760배** |

> **24세션에서는 $1.43과 $0.03의 차이다. 그래서 못 봤다.**
> 720턴 코퍼스는 `O(N²)`를 드러낼 수 없다. **평가 범위가 결론의 범위를 정한다.**

## 결정 동인

1. 드리프트(열화)를 유계로 유지
2. 누적 비용이 `O(N²)`가 되지 않을 것
3. 재작성이 응답 경로에 오지 않을 것 (배치)
4. 유저가 요약을 편집한 경우 존중 ([06 L4](../06-data-model.md) `user_edited_at`)

## 고려한 선택지

| | 방식 | 400세션 비용 | 사슬 깊이 |
|---|---|---|---|
| P1 | 매 세션 **원본 전체** 재독 | **$376** | 1 |
| P2 | 이전 lifetime + 새 세션 요약 | $0.49 | **400** |
| P3 | 평소 증분 + M세션마다 원본 재구축 | $20.35 | ≤ M |
| **P4** | **모든 세션 요약**에서 재작성 | **$9.40** | **2** |

## 결정

> **lifetime 요약은 "모든 세션 요약"에서 다시 쓴다. 원본은 안 읽는다.**

### ⭐ 핵심 통찰 — 드리프트를 만드는 건 빈도가 아니라 **사슬 깊이**다

```
P2 증분   턴 → 세션요약 → lifetime → lifetime → lifetime → …
          깊이가 세션 수만큼 자란다. 400세션이면 400단 사슬이다

P4        턴 → 세션요약 → lifetime
          **세션이 몇 개든 깊이는 항상 2다.** 사슬이 안 자란다
```

세션 요약은 300토큰이라 **400개를 다 읽어도 120K토큰**이고, 원본(5,000,000토큰)의 **2.4%**다.

> **드리프트 유계와 저비용은 상충하지 않았다.**
> 상충한다고 본 건 *"재작성 = 원본 재독"*이라고 **암묵 가정**했기 때문이다.
> 가정을 이름 붙여 적어보고서야 그게 가정이라는 걸 알았다.

## 결과

**좋은 것**
- 원본 재작성의 **1/40** 비용으로 드리프트가 유계다
- 세션 요약이 **재사용 가능한 중간 산출물**이 된다 — 한 번 만들면 lifetime 재작성마다 다시 쓴다
- [ADR-008](ADR-008-provider-model-tiering.md)의 Batch 티어에 그대로 얹힌다

**나쁜 것**
- **드리프트 크기를 안 쟀다.** P4가 P1보다 얼마나 나쁜지는 LLM 없이 모른다. *"깊이 2면 유계"*는 논증이지 실측이 아니다
- 세션 요약이 **품질 상한**이 된다. 세션 요약이 놓친 것은 lifetime에 영원히 안 들어간다
- 400세션이면 입력이 120K토큰이라 **컨텍스트 창을 신경 써야** 한다. 그 이상은 세션 요약을 다시 묶는 3층이 필요하다 — **그때 깊이가 3이 된다**

**중립**
- `session_end_note`([09 peak-end](../09-what-memory-is-for.md))는 세션 요약에 포함되므로 그대로 흘러든다

## 🔴 정정 — 품질 근거를 철회한다 ([실험 19](../11-experiment-results.md))

*"드리프트 크기를 안 쟀다"*고 적어뒀으니 쟀다. **논증이 기각됐다.**

| 단계 | 대장 항목 생존 | 사슬 깊이 |
|---|---|---|
| 원본 턴 | 11/11 | 0 |
| 세션 요약 | **10/11** | 1 |
| lifetime — P4 | **1/11** | 2 |
| lifetime — P2 | **1/11** | 12 |

**깊이 2와 깊이 12가 똑같다.** *"사슬 깊이가 드리프트를 만든다"*는 이 규모에서 지지되지 않는다.

> **이 ADR은 비용 근거만으로 남는다.** P4를 채택하는 이유는 **$376 → $9.4**이지
> 품질이 아니다. 처음 쓴 논증의 절반이 틀렸다.

### ⭐ 대신 더 중요한 것이 나왔다 — 손실은 **압축**에서 난다

```
원본 11/11  →  세션 요약 10/11  →  lifetime 1/11
                              ↑ 여기서 90%
```

12세션 × 3문장을 **5문장으로 줄이는 7배 압축**이 원인이다.
프롬프트에 *"사실·사건·관계 변화만 남겨라"*라고 **명시했는데도** 구체가 먼저 버려졌다 —
고양이 이름·직업·카페인 민감·여동생·2년 선배가 전부 사라지고 *"관계가 냉담했다"*만 남았다.

**설계 함의 — 요약에 사실 보존을 기대하면 안 된다.**
[06 L5](../06-data-model.md)의 사실 계층 분리는 *"갱신·모순 탐지"* 때문이라고 썼는데,
**더 근본적인 이유가 있었다.** 그리고 [실험 13](../11-experiment-results.md)에서
제안안이 G1을 이긴 3문항이 **전부 사실 회상**이었던 것과 정확히 맞물린다.

### 🔴 그리고 압축을 직접 검증했더니 **범인은 내 프롬프트였다**

| lifetime 예산 | 생존 |
|---|---|
| 5문장 (원래) | 2/11 |
| **15문장** | **2/11** — 자리를 줘도 안 담는다 |
| **사실 우선 15문장** | **7/11** — 지시를 바꾸니 돌아온다 |

**예산만으로는 안 된다.** lifetime 지시가 *"타임라인과 **관계 변화**를 남겨라"*였고,
모델은 **시킨 대로 했다.** 사실을 담으라고 안 했으니 예산이 빠듯할 때 먼저 버려졌다.

> 요약이 사실을 못 담는 게 아니라 **내가 담으라고 안 했다.**
> 그런데 지시를 고쳐도 7/11이라 **압축 손실도 함께 작용한다.** 둘 다 원인이다.

⚠️ **세션 12개짜리 결과다.** 100~400세션에서는 깊이 효과가 나타날 수도 있다.
기각한 것은 *"이 규모에서"*다.

## 미해결

- **더 긴 사슬에서 재측정.** 12세션으로는 깊이 효과가 안 보였을 수 있다
- 🔄 **재작성 트리거가 읽을 두 값은 이제 있다** ([ADR-014](ADR-014-relationship-state-machine.md)) — 관계 stage 전이가 요약을 stale로 밀 때 **사유**(`전이:{이전}→{이후}` 접두사, `Memory.stale_row()`로 읽는다)와 **시점**(`digest_meta.stale_since_seq`, **비어 있을 때만** 써서 *첫* 전이 시점이 보존된다)을 남긴다. **미해결로 남는 이유:** 그 값을 읽어 *"낡았지만 경고와 함께 넣을 것인가 / 만료로 볼 것인가"*를 정하는 **서빙 정책이 아직 없다.** [실험 20](../11-experiment-results.md)의 실측은 현재 동작 그대로 — 전이 후 stale 파생물 **주입 0회 / 제외 10회**(`build_context`가 stale이면 무조건 뺀다)
- ~~lifetime 토큰 예산을 늘리면 사실이 남는가~~ → **검증함. 예산만으로는 안 되고 지시가 필요하다**
- **요약 프롬프트를 고칠 것** — `[14 추출 프롬프트](../14-extraction-prompts.md)`에 lifetime 요약 지시가 없다. 추가해야 한다
- 3층이 필요해지는 지점(세션 수)이 미정
- 유저가 편집한 요약을 재작성이 덮어쓰면 안 된다 — `user_edited_at` 처리 절차 미정

🔄 **닫힘 — 서빙 정책이 생겼다 ([ADR-016](ADR-016-summary-layer.md)).** 위 두 번째 항목의 *"서빙 정책이 아직 없다"*는 stale 사유별 3분기(삭제·무효화 → 제외 / `전이:` → 경고와 함께 주입 / E회 경계 초과 → `stale_expired`)와 전역 `STALE_SERVE_POLICY`로 닫힌다. 🔴 **그 항목의 기록값 «주입 0회 / 제외 10회»는 지우지 않고 그대로 둔다** — 그것이 ADR-016의 판정에서 **대조 기준**이었기 때문이다. 새 정책을 켠 실행은 주입 10회 / 제외 0회이고, 옛 동작(`STALE_SERVE_POLICY="exclude_all"`)을 켠 실행이 **같은 분모(심은 digest 2행 × 전이 5회 = 10)에서 이 기록값을 그대로 재현했다.** 🔴 **재현됐기 때문에 델타를 «정책 하나»에 귀속시킬 수 있었다** — 재현되지 않았다면 두 수를 찍은 것일 뿐 귀속이 아니다. `experiments/fsm_probe.py`는 이 값을 코드에 안 박고 **위 줄에서 읽으며**, 못 읽거나 안 맞으면 종료 1을 낸다. **이 줄의 숫자를 고치면 그 판정 앵커가 사라진다.**

## 🔄 wave2 — 전이 한 번의 **LLM 호출 수**를 쟀다 (2026-09-10)

> 이 절은 파일 **끝에** 붙인다 — 위 139번째 줄이 `fsm_probe.py`의 판정 앵커라서, 앞에 끼우면 앵커가 밀린다.
> **재현:** `PYTHONIOENCODING=utf-8 python -B experiments/transition_regen_probe.py` (기록이 있으면 ollama 0회 · `--live`면 다시 잰다)

위 미해결이 적은 «재작성 트리거»(전이 → stale → 재생성)의 **비용**을 이 ADR은 한 번도 세지 않았다. [ADR-016](ADR-016-summary-layer.md)의 I5 주석도 **행 수**(N+2)만 셌다. 셌다:

| | 값 | 분모 |
|---|---|---|
| **전이당 LLM 호출 — 전** | **25회** = 세션 요약 24 + lifetime 1 | 전이 **1회** · 전이가 stale로 민 digest **25키** · `DIGEST_KEEP_SESSIONS` = 24 · legacy `kind='session'` 키 0 |
| **전이당 LLM 호출 — 후** | **25회 — 안 바뀌었다** | 사전 등록이 수리를 허가하지 않았다(아래) |
| 재생성 전후 **프롬프트** 바이트 동일 | 세션 **24/24** · lifetime 0/1 | lifetime은 재료(세션 요약)가 바뀌어 프롬프트부터 다르다 |
| 재생성 전후 **본문** 바이트 동일 | 세션 **0/24** · lifetime **0/1** | `qwen3:8b` · temperature 0 · seed 20260908 · num_ctx 8,192 · 정지 0회 · B 캐시 적중 0 |

일반식: 전이 1회 = `digest_session` 행 수 + (lifetime 행이 있으면 1). legacy 키는 재생성하지 않고 `regen_failed`로 남으므로 호출 0이다.

**사전 등록 (값 보기 전):** *"재생성 결과가 바이트 동일하면 «전이 → 다이제스트 전파»는 오늘의 구현에서 근거가 없다. 한 자리라도 다르면 근거가 있고, 그 다른 자리가 무엇인지가 이 라운드의 결과다."* → **바이트 동일이 아니었다. 그래서 전파는 그대로 두었다.**

🔴 **다른 자리는 `stage`가 아니다.** 프롬프트가 24/24 바이트 동일하다 — 두 생성 함수는 `stage`를 입력으로 받지 않는다. 다른 자리는 **생성기**다: 같은 프롬프트라도 서버의 접두 캐시 적중 길이가 다르면 본문이 달랐다(재생성 전 적중 3–50 tok · 재생성 때 491–552 tok). 대조로 S01 한 키를 일곱 번 보냈더니 적중 493 tok인 다섯 번은 **전부 같았고**, 적중 3 tok(첫 생성)과 0 tok(모델을 내린 뒤)은 **서로도 달랐다**. ⚠️ 한 키·일곱 번의 관측이고 기제(부동소수 경로)는 확인하지 않았다.

🔴 **그래서 «전이 → 재생성»은 «같은 요약을 다시 만드는 비용»이 아니다 — «요약 층 전체를 새 재료 없이 다시 뽑는 일»이다.** 예: S12가 *"사용자는 라면을 먹고 잤으며…"* → *"지우는 이직 준비를 시작했다."* 위 «$9.4» 산술은 이 재추첨을 세지 않는다. 전이가 잦은 도메인이면 호출 수는 전이 수 × (N+1)로 붙는다.

⚠️ **그리고 반대 방향의 사실 하나.** `regen_job.run`은 세션 경계에서 lifetime을 **stale일 때만** 다시 쓴다 — 전이·삭제가 없으면 새 세션 요약이 생겨도 lifetime은 안 바뀐다(대역 생성기로 확인: S04 경계에서 lifetime의 `covers_to_seq` 90 → **90**, 전이가 있으면 90 → 120). 즉 오늘의 구현에서 **전이 전파가 lifetime을 새 세션 쪽으로 끌어오는 사실상 유일한 방아쇠**이고, 위 P4의 비용 산술(세션마다 재작성)과 구현은 다르다.

🔓 **이 전파를 빼는 조건 (관측 가능):** 같은 명령의 `--live` 실행이 세션 **24/24 본문 바이트 동일**을 내는 순간 — 그때 사전 등록 규칙이 «근거 없음»을 준다. ⚠️ 그때도 **lifetime에 제 방아쇠를 먼저 줘야 한다** — 안 그러면 위 «유일한 방아쇠»를 함께 뺀다.

## 🔄 wave3 — 전이당 호출 **25회 → 0회**, lifetime은 세션 경계로 (2026-09-10)

> 이 절도 파일 **끝에** 붙인다 — 139번째 줄이 `fsm_probe.py`의 판정 앵커다.
> **재현:** `PYTHONIOENCODING=utf-8 python -B experiments/transition_regen_probe.py` (재판정 · ollama 0회) · 같은 명령에 `--record experiments/data/TRANSITION_REGEN_W3.json` (wave3 재측정 전문) · `PYTHONIOENCODING=utf-8 python -B experiments/cache_state_repro.py` (F39)

🔴 **위 wave2 절의 사전 등록은 발화할 수 없는 조건이었다.** «본문 바이트 동일»은 서버가 그 접두를 같은 경로로 들고 있을 때만 나오는데(F39 — `docs/12` §3), 재생성은 정의상 첫 생성과 캐시 상태가 다르다. 즉 그 규칙은 전파에 근거가 있든 없든 **«근거 있음»을 내게 되어 있었다.** 규약대로 지킨 것은 옳았고, 규칙이 틀렸다.

## 🔄 괴리 처분 (2026-09-10) — 이 ADR에 붙은 두 줄

> 이 절도 파일 **끝에** 붙인다 — 139번째 줄이 `fsm_probe.py`의 판정 앵커다.

- **위 §결과 «`session_end_note`는 세션 요약에 포함되므로 그대로 흘러든다»는 프로토타입에서 참이 아니다.** P4 템플릿이 `## 다음에`를 요구하지만 `summarize.session_digest`가 그것을 따로 파싱·저장하지 않고 `put_session_digest`의 `session_end_note` 인자는 늘 `None`이다 — 본문 안에 섞여 lifetime으로 흘러갈 수는 있어도 **따로 남는 칸은 비어 있다.** 기록: [ADR-004](ADR-004-write-path.md) «미해결».
- **연구 문서가 위 §결정의 인용문(«원본은 안 읽는다»)을 전이 재생성에 대어 «위반»이라 적었는데, 인용을 잘못 붙였다.** 그 문장은 **lifetime의 입력** 규칙이다 — 같은 절의 도식이 «턴 → 세션요약 → lifetime»이고 세션 요약은 설계상 원본 턴에서 만든다. 전이 재생성의 문제는 규칙 위반이 아니라 **비용과 표류**였고, 그것은 위 wave3 절이 닫았다([docs/17](../17-gap-disposition.md) ⛔5).
