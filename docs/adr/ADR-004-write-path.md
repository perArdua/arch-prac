# ADR-004: 쓰기 경로 — 기억은 언제 어떻게 만들어지는가

- **상태:** 제안됨
- **일자:** 2026-09-03
- **관련:** ADR-002, ADR-008
- **근거 문서:** [06 §4](../06-data-model.md), [05 §1·§4](../05-cost-latency-reality.md), [09 §3](../09-what-memory-is-for.md)

## 맥락

**추출 품질이 메모리 시스템의 상한을 결정한다.** 저장하지 못한 것은 검색할 수 없고, 잘못 추출된 것은 영원히 잘못된 채로 남는다.

동시에 두 개의 모순된 요구가 있다.
- **관계 상태(L2)·씬(L3)은 즉시 반영**돼야 한다. 세션 끝까지 기다리면 *"헤어졌는데 계속 자기야"*가 그 세션 내내 발생한다
- **응답 경로에 LLM 호출을 추가할 수 없다.** 메모리 파이프라인 지연 예산이 200~400ms인데 LLM 호출은 200~800ms다

## 결정 동인

1. TTFT 예산 침범 금지
2. 상태 갱신의 즉시성
3. 원가 (배치·Flex 할인 활용)
4. 실패 시 **조용한 손실 방지**

## 고려한 선택지

1. **매 턴 동기 추출** — 정확하지만 TTFT 파괴
2. **세션 종료 배치만** — 싸지만 상태가 세션 내내 낡음
3. **3단 티어** — 성격별로 분리

## 결정

> **우리는 3번을 선택한다. 그리고 동기 층은 별도 LLM 호출 없이 응답 생성에 얹는다.**

| 티어 | 시점 | 대상 | 비용 |
|---|---|---|---|
| **동기** | 응답 생성과 **동시** | L2 상태 델타, L3 씬, `surfaced_count`, 부채 발생 | **추가 호출 0** |
| **준실시간** | N턴마다 | L4 `session` 요약, L9 부채 등록 | **Flex** 50%↓ (1~15분) |
| **배치** | **세션 종료 후** | L5 사실, L6 사건, L8 해석, importance, L4 `lifetime`, 임베딩 | **Batch** 50%↓ (24h) |

**동기 층의 구현 — 구조화 출력을 응답과 함께 받는다:**
```
응답 본문 + <meta>
  state_delta:   {stage: 헤어짐, last_emotion: 서운함}
  scene_delta:   {place: 집앞}
  used_memories: [event:1204, fact:88]
  new_debt:      "다음에 제대로 얘기하기로 함"
</meta>
```
추가 호출 0, 출력 토큰 ~20개 = 턴당 $0.000075. **`used_memories`가 [L6 `surfaced_count`](../06-data-model.md)를 채운다** — 검색된 것과 실제로 발화에 드러난 것을 구별할 수 있게 되고, 그게 기억의 "신호" 가치를 재는 유일한 방법이다.

## 근거

**세션 종료가 배치 시점인 이유 — 세 가지가 동시에 성립한다:**

| | |
|---|---|
| **품질** | peak-end rule의 "end". 재방문 판단의 절반이 마지막 순간에 결정된다 |
| **비용** | 유휴 시간 시작 → sleep-time compute. Batch 50% 할인 |
| **정보** | 세션 전체가 확정됨 → 요약·해석 생성에 최적 조건 |

**비용 최적 시점과 품질 최적 시점이 일치한다.** 흔치 않은 일이므로 놓치면 안 된다.

**Flex 티어의 발견:** Batch와 **동일한 50% 할인인데 동기 인터페이스**이고 지연이 1~15분이다. 24시간은 너무 길고 즉시성은 필요 없는 작업(세션 중 요약 갱신)이 정확히 여기 들어간다.

**쓰기 비용은 논쟁 대상이 아니다:**
```
세션 1회(50턴) 추출 ≈ $0.0034 (Flash Batch)
턴당 상각 $0.000068 → 주입 비용 $0.0019의 3.6%
```

## 추출기가 반드시 판정할 것 3가지

1. **`realm`** — 픽션 안의 사실인가 밖의 사실인가 (ADR-001)
2. **민감 범주 여부** — 해당하면 추출하지 않는다 (ADR-010)
3. **`importance` / `emotional_weight`** — 롤플레이 현저성은 사실 중요도가 아니라 감정 무게다

## 실패 처리 — 조용한 손실이 최악이다

멀티에이전트 메모리의 4대 실패 모드 중 **stale propagation**(갱신이 조용히 안 됨)이 가장 위험하다. 아무도 모르는 채로 기억이 사라진다.

```
turn.extract_status : pending → done | failed
  실패 → 3회 재시도(지수 백오프)
  최종 실패 → coverage(resolution='extract_failed') 기록
            → 시스템이 "그 시기는 잘 모르겠어"라고 정직하게 말할 수 있음
```
**멱등성:** `fact`의 `UNIQUE(chat_id, source_turn_seq, predicate, object)`가 재시도 중복을 막는다. 🔄 *(w25e · 2026-09-12 · w24b2가 찾음 · 🔓 안 고침 — 스키마 변경)* **이 키에 주어가 없다** — 같은 턴에 다른 주어가 같은 (술어, 값)을 가지면 충돌이다. 갱신 경로는 이제 보류(`held` · «다른 주어의 행»)로 막히지만, **신규 · 병존 경로의 `INSERT OR IGNORE`는 그 행을 조용히 버리고 `created` · `coexist`를 돌려준다**(재현: %TEMP% 사본 · 민수 «직업=의사» 뒤 같은 턴 지우 «직업=의사» → 지우의 행 0 · provenance 0 · 위반 0 · [알고 있는 것]에는 «민수의 직업»만 — 다른 턴이면 둘 다 선다). 오늘 기록 경로에서는 구조적으로 안 난다(소크 적재가 주어를 «지우» 하나로 박는다). 열리는 조건: 스키마 v6(UNIQUE에 주어) · 추출기가 지인 주어를 한 턴에 여럿 낼 때. 처분표 docs/17 §18-5 🔄 *(w31i · 2026-09-12 · w30g)* **조용한 버림 → 기록된 보류.** 신규 · 병존 경로의 INSERT가 0행이면 `held` + provenance `fact_held`로 돌려준다(갱신 경로의 같은 턴 보류와 같은 모양) — 사유가 원인 넷을 가른다: 다른 주어의 행 · 같은 턴에 지운 옛 행 · 같은 턴에 무효화된 옛 행 · 같은 턴에 이미 있는 같은 행(주어 None). 시험 `prototype/tests/test_write_guards.py`의 `TestUniqueWithoutSubject` 8. 자료 손실은 그대로다(그 행은 여전히 안 선다) — 달라진 것은 손실이 기록된다는 점이다. 스키마(UNIQUE에 주어)는 v6(추출기)와 함께 · 처분표 docs/17 §18-6

## 결과

**좋아지는 것**
- TTFT를 전혀 건드리지 않으면서 상태가 즉시 갱신된다
- 무거운 처리가 전부 50% 할인 티어로 내려간다
- 추출 실패가 침묵하지 않고 abstention으로 전환된다 🔄 *(w24c · 2026-09-12 · Fable 검토 C8 둘째 · R10 · 계획 K5 · 사용자 결정 Q7 = 보류)* **같은 턴 A→B→A는 셋째 진술을 보류(`held`)로 남기고 B를 유지한다** — 한 턴에 값이 셋인 것은 추출기의 흔들림이고, «덜 확신하면 못 덮는다»(U10 방어선)와 같은 처분이다. 오늘은 셋째 진술이 위 §실패 처리의 멱등 UNIQUE에 걸려 예외가 나는데, 그 전에 B가 이미 무효화돼 다음 커밋 뒤 유효 값이 0개가 된다(자료 손실 · 2026-09-12 w23 재현 R10 그대로). 구현은 B2 레인(`memory.py` 줄 수 중립 · 아직 안 됨)

**감수하는 것 / 리스크**
- ⚠️ **모델이 서사와 메타를 동시에 생성하면 서사 품질이 떨어질 수 있다.** 이게 이 ADR의 가장 큰 미검증 가정이다
- 대안: 응답 후 비동기 경량 분류기 → 지연 0(응답은 이미 나감), **1턴 늦게 반영**
- → **실험 D9로 결정한다**

## 재검토 트리거

- **D9에서 구조화 출력이 품질을 3%p 이상 떨어뜨리면** → 비동기 1턴 지연으로 전환
- 세션 경계 감지(N분 무응답)가 부정확해 배치가 자주 헛돌면 → 명시적 세션 종료 신호 도입
- Flex 지연이 15분을 자주 넘기면 → session 요약을 동기 층으로 이동 (비용 증가 감수)

## 미해결

> 🔄 **2026-09-10 괴리 처분이 이 절을 만들었다** ([docs/17](../17-gap-disposition.md) 검D5 · 검기타-5 · R1 · R2). 전제: 프로토타입에는 **추출기가 없다** — `soak.ingest`가 대장을 그대로 넣는다(이미 기록: `prototype/README.md` · [docs/13](../13-prototype.md) «이 프로토타입이 아닌 것»). 아래는 그 전제 **밖에서** 드러난 것이다.

- 🔴 **위 «실패 처리 — 조용한 손실이 최악이다»의 계층이 통째로 비어 있다.** `turn.extract_status`는 DDL(기본값 `'pending'`)뿐이고 **갱신하는 코드가 0곳**이다. `pending → done | failed`·재시도 3회·`coverage(extract_failed)` 어느 것도 없다. [docs/16](../16-design-elements.md) 요소 지도가 이 칸을 ✅로 적었었다 — 제자리에서 «저장 형식만»으로 고쳤다. 🔓 **열리는 조건:** 어느 코드든 `extract_status`를 `'pending'` 밖의 값으로 **처음 쓰는 순간** — 그때 실패 경로의 시험이 같이 와야 한다.
- **`session_end_note`가 만들어지지 않는다.** P4 템플릿은 `## 다음에`를 요구하지만 `summarize.session_digest`가 그것을 파싱·저장하지 않고 `put_session_digest`의 인자는 늘 `None`이다. peak-end([09](../09-what-memory-is-for.md))의 데이터 계층이 끊겨 있다([ADR-013](ADR-013-summary-regeneration.md) 끝 절). 🔓 `digest_session.session_end_note`가 NULL이 아닌 행이 처음 생기는 순간.
- **배치 층이 없다.** importance 재계산이 없고(`add_event`의 importance = 인자 또는 `emotional_weight`), 임베딩은 쓰기 경로에서 동기로 만든다(`embed` 모드일 때만). 위 §결정의 Batch 티어는 설계로만 있다.
- **술어 어휘가 두 벌이다.** [docs/14](../14-extraction-prompts.md) 표는 **25종**, 코드의 `PREDICATE_CARDINALITY`·`PREDICATE_MUTABILITY`는 **8종**, `PREDICATE_STANDING`은 **9종**(표에 없는 `지인_직업`·`관계_배경` 포함)이다. 표 밖 술어는 기본값(`many`/`mid`)으로 떨어지고 **상시 주입에서 빠진다** — `이름`·`나이`·`호칭`도. ⏸ 통일은 미뤘다(docs/17 밖E10). 🔓 **열리는 조건:** 추출기가 대장 밖 술어를 **한 건이라도** 내는 순간.
- 🔄 **위 항목의 대가를 쟀다 — 2026-09-10 레인 B** (`experiments/predicate_vocab_cost.py` · 두 코퍼스를 `soak.ingest` 무변경으로 임시 DB에 적재 · LLM 0회). 대장이 실제로 쓰는 술어는 `eval` **8종/12행** · `eval2` **12종/13행**이다.
  - **표 밖으로 떨어지는 것:** `eval`은 코드 카디널리티 표 밖 **2/8종 · 2/12행**(`관계_배경`·`지인_직업` — 둘 다 docs/14 표에도 없다) · `eval2`는 **12/12종 · 13/13행**(코드에도 docs/14 표에도 없다). 앞 파도의 «`eval2` 적중 0/12»를 다시 뽑아 같은 값을 얻었다.
  - **ⓐ 대장이 «갱신»이라 적은 쌍이 병존으로 끝난 수:** `eval` 0/1 · `eval2` **1/1** — `운영_버전` v2.4 → v3.0이 기본값 `many` 때문에 둘 다 유효로 남는다. 대장이 무효화한 옛 값(G002)이 런타임에서 계속 유효하고 검색으로 닿는다.
  - **ⓑ 유효 사실 중 상시 블록에 안 실린 수:** `eval` 4/11(전부 `일상_사소` — 표도 상시가 아니다) · `eval2` **12/12** — 그 방의 상시 블록은 `(아직 없음)` 한 줄이다. **사실이 열둘 있는데 모델에게 «아는 것이 없다»고 알린다.** 근거가 사실인 문항 7개가 전부 검색으로만 닿는다.
  - **ⓒ `superseded_by`가 채워진 행:** `eval` 1(대장 기대 1) · `eval2` 0(대장 기대 1). 앞 파도의 값과 같다.
  - 🔴 **25종으로 넓혀도 아무것도 안 움직인다.** 세 클래스 속성을 런타임에 재바인딩(`try/finally` 복원 · 객체 동일성 확인)한 **합집합**(코드 ∪ docs/14) 팔에서 두 코퍼스 모두 ⓐⓑⓒ 변화 0 · upsert 동작이 바뀐 사실 0이다. **대체**(docs/14 25종만) 팔은 `eval`에서 오히려 나빠진다 — ⓑ +2(`관계_배경`·`지인_직업`이 표에 없어 상시에서 빠지고, 근거가 상시 블록에 하나도 없는 문항이 0 → 1이 된다). 코드와 표가 같은 술어에 다른 값을 주는 곳은 0이다. → **이 두 코퍼스에서 대가를 만드는 것은 «8 대 25»가 아니라 대장 술어가 두 어휘 모두의 밖에 있다는 것이다.** 사전 등록한 «25종 확장은 ⓐⓑⓒ 중 하나를 움직인다»는 **거짓**으로 판정됐다. 계수가 원래 안 움직이는 것이 아님은 심어서 봤다 — `운영_버전`을 `one`으로 심으면 ⓐ 1→0 · ⓒ 0→1, `소속`을 상시로 심으면 ⓑ 12→11.
