# 0911 사용자 결정 기록 (초안 — 결정 기록 레인이 원장에 옮긴다)

> 사용자가 판단을 맡겨 오케스트레이터가 근거와 함께 초안을 냈고 → **사용자가 검토해 셋을 고쳤다**(θ·엔진은 «성급하다 — 이 실험에서 그랬으니 안 쓴다는 근거와 추후 필요한 경우를 명시하라», ollama는 «다운그레이드가 낫다»). 아래가 고친 판이다.

## 1. ollama — **다운그레이드하지 않는다. 재채점은 기록 판 키로 · 측정은 막지 않는다** (사용자 결정 — 처음엔 «다운그레이드»였다가 근거를 보고 바꿈)

- 사용자 물음: «버전 차이가 실험에 유의미한가 — 모델은 같지 않은가.» **쟀다:**
  - 모델 다이제스트: 두 판 **동일**(`500a1f067a9f…`).
  - 같은 프롬프트 칸 115쌍(오늘 아침 오염본)에서 0.33.3과 0.34.0의 답이 글자까지 같은 것 **5/115** · 유사도 중앙값 0.53. 🔴 그러나 **같은 판에서 다시 만들어도** 본문 동일 0/24(F39) — 판 차이를 따로 **가를 수 없다.** 새로 만든 답은 판과 무관하게 옛 답과 다르다.
  - 🔴 결정적 부분은 판과 무관했다: `digest_budget` 저울 대조의 실측 `prompt_eval_count`가 0.34.0에서 **1,296 tok · 108 tok — 0.33.3 기록과 글자까지 같다**(토크나이저는 모델 파일 안에 있다).
- 결론: 판이 실제로 걸리는 곳은 **캐시 키 하나**다. 기록값은 옛 답 텍스트의 **재채점**이고 그때 ollama는 불리지 않는다.
- **구현(오케스트레이터):** `prototype/llm.py` 끝 절 — `key_runtime(now)`(`run_all` 아래에서 캐시 키를 **기록 판**으로) · `measure_prompt()`(체크포인트를 안 채우는 측정 — 가드가 막지 않되 **검사를 «소비»하지 않는다**: `raw_generate`의 `_checked = not _MEASURING`) · `_guard_regen`은 여전히 **실제** 런타임으로 대조해 빗나간 생성을 77로 멈춘다(대체한 키로 새 답이 저장되는 일 없음). 배선: `response_quality.py`의 `Generator(LLM.key_runtime(rt))` · `digest_budget.py`의 `llm.measure_prompt(probe, num_predict=1)`. 시험 `prototype/tests/test_llm_regen_guard.py` 7건(새 3) · 심은 위반 셋 발화(측정이 검사를 소비 · 키가 늘 현재 판 · 측정까지 막음).
- **끝-끝:** `run_all` 조건(`MEMARCH_FORBID_REGEN=1`)에서 `response_quality` 종료 0 · **생성 0건 · 캐시 히트 1368건**(어젯밤 기준선과 같은 줄) · `digest_budget` 종료 0 · 체크포인트 JSON 전체 지문 전후 동일 · `RESPONSE_CACHE.json` `a809ae2a…` 그대로. → **SKIP 2가 사라진다.**
- 자동 업데이트: **사용자가 나중에 직접 끈다**(Ollama 앱 설정 `auto_update_enabled`). 꺼지지 않아도 위 방식은 다음 판에서도 버틴다.
- 남는 것: F39 그대로(새 생성은 판과 무관하게 불안정) · F40 가드 그대로.

## 2. θ 스위치 (`THETA_ON_SCORE`) — **이번 실험의 조건에서는 쓰지 않는다.** 설계 기각이 아니다

**판단이 서는 범위 (실험 33의 조건 — 이 중 하나가 바뀌면 판단이 다시 열린다):**
- 관련도 척도가 **어휘**(`lexical` bigram 덮기율)다 — `rel`이 0에 원자로 몰린 분포.
- 코퍼스가 **합성 5열**(eval · eval2 · eval3 세 레짐, 저자 하나)이고 방 하나다. 🔄 *(w14close · 2026-09-12) 외부 인간 대화 1열(실험 34 · AI Hub 71630 Validation 8,000대화 · 사람-사람 크라우드 · 존댓말 설계)을 따로 쟀다 — 아래 ⑤ · ②의 전제만(각 줄 끝) · 이 판단은 그대로다*
- 질의가 **짧다**(채점 문항 전부 bigram ≤ 20).
- 판정 지표가 **심은 근거의 회상 + 오주입**이다(응답 품질이 아니다).
- `surfaced_count`는 기본 경로에서 **0**이고, 페널티 축은 **모의 `<meta>`**에서만 쟀다(되먹임 없음).
- θ는 **«현행과 같은 실제 컷 비율»** 한 규칙으로만 재유도했다.

**관측값:** 현행 조합 «켬 나음» 0/5열 · eval3 세 열 «켬 나쁨»(오주입 합 90/58 · 91/61 · 90/45) · 전 칸 «켬 나음» 0.

**추후 필요해질 수 있는 경우 (각각 관측 가능한 방아쇠):**
1. **중요도로 약한 관련도를 구제해야 할 때** — θ가 `rel`에 걸리면 `rel < θ`인 기억은 중요도·정서 무게와 무관하게 **항상** 잘린다. 의역·간접 질의로 «중요한데 못 꺼냈다»가 실사용에서 관측되면 θ를 최종 점수에 거는 것이 그 구제 경로다.
2. **관련도 척도가 연속일 때** — `embed` 모드처럼 `rel`에 0 원자가 없는 척도에서는 «rel에 컷»과 «score에 컷»의 차이가 달라진다. 실험 33은 어휘 척도에서만 쟀다. — 외부 인간 대화(실험 34)에서: **전제 성립**(연속 척도의 `rel`에 0 원자 없음) — bge-m3 코사인의 방해 행 `== 0` 0/3,842,595(합본 · 목록 해석 · 최소 0.148) · 0/197,919(방) · 같은 방해 행의 어휘 `rel == 0` 몫 0.953 · 0.900(글자 집합 해석) · 등록상 판정 없음 · 방아쇠 자체(제품이 연속 척도를 쓰는가)는 이 측정이 말하지 않는다 · 실사용 관측이 아니다 · 🔄 *(w19 · 2026-09-12 · 제품 경로 `embed` 모드) embed θ 실제 컷 0.40(84,221/210,133) · 유도 0.80 · 모든 측정 호출 `stale_theta`(12,214/12,214) — 외부 인간 대화 · 실사용 아님 · docs/11 «실험 결과 (34)» 부록 I-2*
3. **반복 노출을 «잘라야» 할 때** — 실제 응답의 `used_memories`가 흘러 `surfaced_count`가 쌓이고 «같은 기억 반복»이 관측되면: θ가 `rel`에 걸린 동안 페널티는 **순서만 바꾸고 못 자른다.**
4. **평가 기준이 바뀔 때** — 오주입보다 **능동 회상**(묻지 않아도 꺼내기)을 우선하는 제품 결정이 나면 실험 33의 판정 규칙 자체가 바뀐다.
5. **질의가 길어질 때** — bigram > 20인 질의에서 θ=0.05의 «겹침 0만 버린다» 성질이 깨진다(eval3 레인) → 컷의 뜻이 달라진다. — 외부 인간 대화(실험 34)에서: **전제 성립** — P(bigram > 20) 87,229/213,866 = 0.408 [0.406, 0.410](Validation 8,000대화의 세션 k ≥ 2 발화 전부) · 그런 질의 중 θ가 «겹침 0이 아닌» 행을 1개 이상 자르는 몫 42,734/87,229 = 0.490 · 합성 채점 문항은 0/48 · 0/18 · 0/13(나란히 · 화살표 없음) · 실사용 관측이 아니다(사람-사람 · 존댓말 설계) · 🔄 *(w18 · 2026-09-12) 교차 세션 되묻기 실례: 후보 1(bigram 26)에서 방 저장소 10행이 전부 θ에 거절돼 빈 반환 — 라벨 40개 중 한 건 · 판정 아님 · docs/11 부록 I-3*

**그때 할 일:** 실험 33 하니스(`experiments/theta_grid.py`) 재사용 · 새 θ 규칙(예: 실제 컷이 아니라 **오주입을 겨냥한** θ)을 **값 보기 전에 사전 등록** · 스위치 코드는 그래서 **남겨 둔다.**

## 3. 표 밖 술어 (`UNKNOWN_PREDICATE_POLICY`) — **`legacy` 유지**

(오케스트레이터 판단 그대로 — 사용자 이의 없음.) 두 후보 모두 켤 전제가 오늘 없다: 단일값은 «추출기가 주어를 넣는다 · 표 밖 다중값이 드물다», 상시는 «상시 블록 크기 상한 + 함정 거르기». 다시 볼 때: 술어를 내는 추출기가 생길 때 · 상시 블록 상한이 생길 때.

## 4. 엔진 (OpenSearch+nori · Postgres+pg_bigm) — **이번 실험의 조건에서는 도입하지 않는다**

**판단이 서는 범위 (실험 32의 조건):**
- 합성 코퍼스 · **방 하나** · 색인 최대 **3,000행** · 프로세스 하나. 🔄 *(w14close · 2026-09-12) 외부 인간 대화 1열(실험 34)을 따로 쟀다 — 아래 ③ · ④의 전제만(각 줄 끝 · 방 p50 15행 · 합본 p50 241행 — 규모 아님) · 이 판단은 그대로다*
- 엔진은 **기본 설정**이다(nori 사용자 사전 없음 · 품사 필터 기본 · BM25 k1/b 기본 — 튜닝 안 함).
- 지표는 **검색까지**(순위 V1 · 파이프라인 V2) — 응답 품질이 아니다.
- 홀드아웃이 열당 **23문항** — «검출 안 됨»은 «같다»가 아니다.
- **dense · 하이브리드 · pgvector는 비교에 없다.**

**관측값:** 구현 요인(엔진 자체)이 순위를 **0/175** 바꿈 · 기본 설정 엔진이 현행을 넘는 것 검출 안 됨(V2에서 오주입이 는 열 둘) · 메모 뒤 현행 p50 ≈ 4.3 ms ≈ Postgres GIN ≈ 4 ms(3,000행).

**추후 필요해질 수 있는 경우:**
1. **규모** — 한 방 색인이 메모 뒤 웜 곡선의 20 ms 교차(≈ 8.7k~10.4k행)에 다가갈 때, 또는 **콜드 조회가 지배**하는 부하(프로세스 재시작이 잦으면 메모가 콜드를 못 줄인다).
2. **방 여럿 · 프로세스 여럿** — 한 프로세스가 방 여럿을 맡아 메모 상한(`MEMO_ROWS=16384`) **절벽**이 관측될 때 · 여러 워커가 같은 저장소를 쓰는 **동시성·내구성** 요구(SQLite 쓰기 잠금) → Postgres(ADR-003 «인프라는 Postgres 하나»).
3. **형태소가 필요할 때** — 실사용에서 활용형·존댓말 불일치로 인한 누락이 관측되거나(실험 31의 `됐`·`입` 같은 자리), **고유명사 사전(L7) + 튜닝한 nori**가 사전 등록 홀드아웃에서 이득을 낼 때. — 외부 인간 대화(실험 34)에서: 등록 판정 **성립 안 함(이 모집단)** — P2 = P(어휘 하드 누락 ∧ nori 겹침 > 0) 224/12,214 = 0.018 [0.016, 0.021] < 문턱 0.05. 🔴 **등록 결함 — 닿을 수 없는 문턱:** 분자가 어휘 하드 누락 390/12,214(Wilson 상한 0.035)의 부분집합이라 문턱에 닿을 수 없었다 · 사후 표지(판정 아님) 하드 누락 중 nori 겹침 > 0 몫 224/390 = 0.574 · 곁: nori 기본 설정은 A0보다 recall@1 **손실 검출**(방 −0.0725 · 합본 −0.1384 · 짝 12,214 · 비관 순위 — 낙관 순위였다면 −0.023 · −0.067 · 사후) · 실사용 관측이 아니다(대리 지표 · 사람-사람 · 존댓말 설계) · 🔄 *(w18 · 2026-09-12) M3 교차 세션 회상(사람 · LLM 라벨 · n_r 13)에서 nori 대 어휘 recall@1 불일치 0:0 — 검출 안 됨(«같다»가 아니다) · docs/11 부록 I-3*
4. **dense·하이브리드를 규모에서 돌릴 때** — 벡터 색인(pgvector HNSW · OpenSearch k-NN)이 필요해지면. — 외부 인간 대화(실험 34)에서: (규모 아님 — 방 p50 15행 · 합본 p50 241행) bge-m3 코사인이 A0보다 recall@1 **이득 검출**(방 +0.056 · 합본 +0.121 · 짝 12,214 · 비관 순위 · 목록 해석) — 🔴 낙관 순위였다면 방 −0.005 · 합본 +0.015(사후 · 대부분 비관 순위가 어휘 동점을 벌한 몫) · 방아쇠(벡터 색인이 필요해지는 규모)는 이 측정이 말하지 않는다 · 🔄 *(w19 · w15tie · 2026-09-12) 제품 경로 같은 층에서 D1 − A0 = +0.069 [+0.064, +0.074](사후 표지 · 짝 12,214) — 제품 순서는 V1 비관과 같은 규칙이고 A0는 동점과 θ 컷 둘로 잃는다 · M3(n_r 13)에서는 dense 대 어휘 2:0 검출 안 됨(w18) · docs/11 부록 I*
5. **운영 전제가 바뀔 때** — 제품이 이미 Postgres를 운영하면 pg_bigm 도입 비용이 작다(소스 빌드 이미지 `experiments/engine_infra/`).

**첫 후보 순서:** Postgres(pg_bigm · pgvector) → OpenSearch. **그때 할 일:** 실험 32 하니스(`experiments/engine_arms.py`) 재사용 · 튜닝 팔은 훈련 분할에서만 · 사전 등록.

## 5. 컨테이너 — **떠 있게 둔다** (사용자가 Docker를 다시 켰다 · 오케스트레이터가 `docker start`로 둘을 다시 올림)

`memarch-os`·`memarch-pg`를 다시 올렸다(`docker start`). 그래서 `run_all`의 실험 32 단계가 돈다(≈ 10분 — Bash 10분 한도는 `nohup … &` + 폴링). Docker 잔여 폴더 `run.stale-20260911`은 0바이트 죽은 소켓 항목 둘 — 사용자가 손으로 지워도 된다(오케스트레이터는 지우지 않는다).
